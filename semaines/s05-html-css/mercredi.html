Mercredi 04/11 — Atelier guidé & autonomie

Formateur

Kevin Bardoux

Date de publication

mercredi 4 novembre 2026

Matin : atelier guidé, avec le formateur. Après-midi (12 h 45 – 17 h) : en autonomie, seul ou en binôme.
À déposer ce soir : une capture de votre composant (mobile et bureau) et de vos cibles CSS. Le composant est votre premier défi au portfolio : il sera publié jeudi, après votre page personnelle.

ImportantLe minimum du jour
  • Matin : node --test css-exercices.test.js au vert (exercice 4), puis un composant (Frontend Mentor ou carte de profil), à 375 px et en bureau, avec ses deux captures.
  • Après-midi : trois défis CSS reproduits (dossier defis-css), vérifiés avec comparer.html, une capture chacun.

Le reste (rubriques « Si le temps le permet » et encadrés « Défi ») est la suite naturelle, pour ceux qui avancent.

Objectifs de la journée

  • Choisir une unité adaptée : rem, %, px.
  • Intégrer un composant fidèle à la maquette, 375 px et bureau.
  • Ranger le guide de style de la maquette en variables CSS.
  • Reproduire une cible visuelle au pixel près, en CSS.
  • Lire un énoncé en anglais.
  • Avancer ensuite votre page personnelle.

Matin — Atelier guidé : TP — Frontend Mentor : intégrer un composant HTML/CSS

Rappel (5 min)

  1. Quel attribut relie un label à son champ ?
  2. Que fait un .gitignore ?
  3. Que donne '4' * 2 ?

Trois questions courtes, sans regarder vos notes : la veille, la semaine passée, puis plus loin. Répondez sur une feuille ; la correction suit, à l’oral.

Apport — Les unités (15 min)

  • Pourquoi : une page lisible quand le visiteur agrandit le texte.
  • rem suit la taille de texte choisie par l’utilisateur.

Pourquoi. Certaines personnes agrandissent le texte dans leur navigateur. Une taille fixe les en empêche.

Définition. px est une taille fixe, à réserver aux bordures fines ; rem est relative à la taille de texte choisie par l’utilisateur ; % est relative à l’élément parent, pratique pour les largeurs ; em dépend de la taille du texte du parent, ce qui la rend moins prévisible que rem (MDN Web Docs, s. d.-c). Pour le texte, préférez rem : c’est plus accessible.

Exemple.

body       { font-size: 1rem; }
.conteneur { width: 90%; max-width: 60rem; margin: 0 auto; }
.carte     { border: 1px solid #ccc; }

Avant / après : deux paragraphes, l’un en font-size: 16px, l’autre en font-size: 1rem. Avant, avec la taille de texte par défaut du navigateur ; après, quand le visiteur la règle sur 24 px.

Les quatre unités, côte à côte : la même barre, dans le même parent ; la largeur affichée a été mesurée dans le navigateur.

Pas à pas.

  1. Dans les réglages du navigateur, agrandissez la taille du texte.
  2. Rechargez la page : les textes en rem grandissent, ceux en px non.
  3. Remettez la taille par défaut.

Unités — attention et vérification

AvertissementAttention

Un texte en px ne grandit pas quand le visiteur agrandit le texte. Pour les tailles de texte, rem.

  • Vérifiez : quelle unité pour une largeur de 90 % du parent ?

Exercice 4 — Le conteneur (10 min)

  1. Dans css-exercices/style.css : exercice 4, le conteneur.
  2. Largeur en %, largeur maximale en rem, centré.
  3. Réussi si : node --test css-exercices.test.js passe en entier.

Niveau : guidé.

Enregistrer (1 min)

Dans le terminal, depuis ~/dwwm/dwwm-tp/semaine-05 :

git status
git add css-exercices/style.css
git commit -m "Ajoute le conteneur de l'exercice 4"

Réussi si : git status affiche rien à valider, la copie de travail est propre.

L’activité

  • Outil : Frontend Mentor, des maquettes à intégrer.
  • Objectif : un composant débutant, mobile et bureau.
  • Pourquoi : de la maquette à l’interface ; défi au portfolio n° 1.
  • Preuve : deux captures, à 375 px et en plein écran.

Frontend Mentor propose des maquettes de composants et de pages à reproduire en HTML et CSS (Frontend Mentor, s. d.). Choisissez un défi de niveau débutant ; lisez l’énoncé en anglais en entier avant de coder. Pour télécharger les fichiers d’un défi (maquettes, images, guide de style), il faut un compte Frontend Mentor ; la connexion avec votre compte GitHub suffit. Si vous ne souhaitez pas créer de compte, faites l’alternative ci-dessous. Ce composant est le premier des deux défis obligatoires de votre portfolio (le second est en semaine 12) : les conditions sont sur la page Finition visuelle.

Déroulé de l’atelier

  1. Lancement (10 min) : lire une maquette, ensemble.
  2. Pratique accompagnée : HTML d’abord, puis le style mobile.
  3. Point d’étape (10 h 30) : un écart fréquent, corrigé au tableau.
  4. Mise en commun (11 h 25) : deux intégrations comparées.

Au lancement, le formateur projette une maquette et la découpe avec le groupe : quelles zones, quelles balises sémantiques, quelles mesures relever dans les outils du navigateur ? À la mise en commun, deux stagiaires montrent leur composant à 375 px : qu’est-ce qui le rend fidèle à la maquette ?

Consignes

  1. Lisez l’énoncé et observez la maquette mobile, puis bureau.
  2. Écrivez d’abord le HTML sémantique, sans aucun style.
  3. Recopiez le guide de style en variables, dans :root (mardi).
  4. Polices : téléchargez-les et déclarez-les avec @font-face.
  5. Stylez pour le mobile, puis élargissez l’écran.
  6. Comparez à la maquette ; notez et corrigez trois écarts.

Niveau : semi-guidé.

Le dossier du composant, en ligne de commande, avant l’étape 1 :

cd ~/dwwm/dwwm-tp/semaine-05
mkdir composant-fm
cd composant-fm
mkdir fonts
touch index.html style.css

Extrayez dans composant-fm l’archive du défi téléchargée sur Frontend Mentor (maquettes, images, guide de style). Avec la carte de profil, le dossier composant-carte existe déjà dans le kit : créez seulement fonts, avec mkdir composant-carte/fonts si vous hébergez une police.

Les polices du guide de style, hébergées dans votre projet

Le guide de style (style-guide.md) indique souvent une police Google, avec un lien vers Google Fonts. Ne chargez jamais une police depuis les serveurs de Google : chaque visiteur de votre page enverrait son adresse IP à Google. Téléchargez le fichier et hébergez-le dans votre projet.

  1. Notez le nom de la police dans le guide de style, par exemple Outfit.
  2. Ouvrez le dépôt public des polices de Google sur GitHub, dossier ofl/ puis le dossier de la police en minuscules, par exemple ofl/outfit (Google, s. d.). Vous devez voir : un fichier .ttf (par exemple Outfit[wght].ttf) et le fichier OFL.txt, la licence.
  3. Vérifiez la licence : OFL.txt (SIL Open Font License) autorise à utiliser et à héberger la police dans votre projet.
  4. Ouvrez le fichier .ttf, puis le bouton de téléchargement (Download raw file).
  5. Rangez-le dans le dossier fonts/ de votre projet (créé plus haut avec mkdir fonts), renommé sans crochets : fonts/Outfit-VariableFont_wght.ttf. Copiez OFL.txt à côté.
  6. Déclarez la police en haut de style.css, puis utilisez-la :
@font-face {
  font-family: "Outfit";
  src: url("fonts/Outfit-VariableFont_wght.ttf") format("truetype");
  font-weight: 100 900;
  font-display: swap;
}
body { font-family: "Outfit", sans-serif; }

Réussi si : dans les outils du navigateur (F12), onglet Réseau, la police vient de votre dossier fonts/, et aucune requête ne part vers fonts.googleapis.com ou fonts.gstatic.com.

@font-face déclare une police à partir d’un fichier (MDN Web Docs, s. d.-b) ; font-weight: 100 900 indique que ce fichier unique contient toutes les graisses (police variable). sans-serif reste la police de secours, le temps du chargement.

AstuceSi vous êtes bloqué
  • Mesurez les écarts dans les outils du navigateur (F12) : taille de police, marges, couleurs.
  • Travaillez par petites étapes : une zone du composant à la fois.
  • Demandez à CS50.ai d’expliquer une propriété CSS, jamais d’écrire le code.

Après-midi — Autonomie : TP — CSSBattle : reproduire une cible en CSS

L’activité

  • Outil : le dossier defis-css de l’archive, hors ligne, sans compte.
  • Objectif : 3 défis au moins ; les 8 au mieux.
  • Pourquoi : maîtriser tailles, positions et couleurs.
  • Preuve : une capture de chaque défi réussi, en mode différence.

Niveau : autonome.

NoteAutonome

Vous allez bloquer : c’est voulu, c’est le métier. Méthode :

  1. lisez le message d’erreur en entier ;
  2. cherchez-le dans la fiche Lire un message d’erreur ;
  3. lisez la documentation ;
  4. après 15 minutes bloqué sur le même point, demandez.

Les huit défis CSS

  1. Dossier defis-css : cible-1.png à cible-8.png (400 × 300 px).
  2. Un fichier de départ par cible : defi-1.html à defi-8.html.
  3. Ouvrez comparer.html avec Live Preview : choisissez le défi.
  4. Réussi si : en mode différence, il ne reste que du noir.
  • Puis avancez votre page personnelle.

comparer.html affiche votre page defi-N.html et pose la cible exactement par-dessus : le curseur règle la transparence de la cible ; le mode différence noircit tout ce qui est identique, et montre en couleur ce qui diffère. Chaque fichier de départ donne un indice en commentaire. Visez d’abord la ressemblance, puis la sobriété du code.

Indice pour le défi 2 : un élément en position: absolute se place à une distance précise (left, top, bottom) des bords de son parent, si ce parent est en position: relative (MDN Web Docs, s. d.-a). C’est la seule propriété nouvelle des huit défis ; les autres reprennent le box model, Flexbox (jeudi, pour aller plus loin) et Grid.

Parcours de remédiation de la semaine

Trois niveaux, au choix

  • À faire si l’activité est terminée, ou au soutien pair à pair du mardi.
  • Niveau 1 — Consolider : sélecteurs, box model, CSS Diner.
  • Niveau 2 — S’entraîner : la carte de profil.
  • Niveau 3 — Aller plus loin : les huit défis CSS, en code minimal.
  • Le détail de chaque niveau est dans le support.
  • Niveau 1 — Consolider
  • Niveau 2 — S’entraîner
  • Niveau 3 — Aller plus loin
  • Refaites les exercices CSS 1 à 4 de mardi dans un nouveau fichier, sans regarder votre première version.
  • CSS Diner : les sélecteurs en jeu, jusqu’au niveau 15 au moins (capture du dernier niveau réussi) (flukeout, s. d.).
  • Demandez à CS50.ai un quiz sur la spécificité (5 questions).
  • Faites la carte de profil, même si vous avez fait Frontend Mentor.
  • Reprenez le formulaire de votre page personnelle : chaque champ a-t-il son label ?
  • Enchaînez les huit défis CSS du dossier defis-css, vérifiés avec comparer.html.
  • Refaites un défi avec le moins de code possible : combien de lignes ?
