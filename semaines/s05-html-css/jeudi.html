Jeudi 05/11 — Flexbox, Grid et mobile first

jeudi 5 novembre 2026

Compétences visées : C3 · communiquer (anglais)
Livrable : la page personnelle mise en page en mobile first, node --test layout.test.js au vert.

ImportantLe minimum du jour
  • Flexbox Froggy : les 24 niveaux ; Grid Garden : le niveau 12 au moins.
  • node --test layout.test.js au vert, sans barre de défilement horizontale à 375 px.
  • La page personnelle publiée sur GitHub Pages, en HTTPS.

Le reste (rubriques « Si le temps le permet » et encadrés « Défi ») est la suite naturelle, pour ceux qui avancent.

Objectifs

  • Aligner et répartir des éléments avec Flexbox.
  • Construire une grille avec Grid, et choisir entre les deux.
  • Écrire une mise en page mobile first avec une media query.
  • Publier sa page sur GitHub Pages.

Comment se passe la journée. Le matin, deux notions : Flexbox et Grid ; l’après-midi, mobile first, juste avant de mettre en page votre page personnelle, puis la publication sur GitHub Pages. Chacune suit le même ordre : pourquoi, définition, exemple, pas à pas, erreur fréquente, vérification ; un encadré « À retenir » termine chaque demi-journée.

Apport 1 — Flexbox (10 min)

  • Pourquoi : aligner des éléments sur une ligne, sans calcul.
  • Flexbox : un parent display: flex répartit ses enfants sur un axe.

Pourquoi. Un menu dont les liens s’alignent et se répartissent, une carte dont l’image et le texte se placent côte à côte : avant Flexbox, il fallait des calculs fragiles.

Définition. Flexbox dispose les enfants d’un élément sur une dimension, en ligne ou en colonne (MDN Web Docs, s. d.-a). justify-content règle l’axe principal, align-items l’axe secondaire, gap l’espace entre les éléments ; flex-wrap: wrap les fait passer à la ligne si la place manque.

Démonstration en direct, à ouvrir dans le navigateur : justify-content et align-items sur un menu de trois liens. Elle se règle au clavier (Tab, puis les flèches) ou à la souris.

Exemple.

.menu {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: 1rem;
}

Pas à pas. Le formateur applique chaque ligne au menu de sa page, l’aperçu ouvert.

  1. display: flex sur le nav : les liens se mettent en ligne.
  2. justify-content: space-between : ils se répartissent sur toute la largeur.
  3. align-items: center : ils se centrent en hauteur.
  4. gap: 1rem : un espace régulier entre eux.

Les valeurs, en images

Chaque vignette est le rendu réel de son code : trois enfants A, B, C dans un parent en pointillés, qui a display: flex.

justify-content : la répartition sur l’axe principal.

align-items : l’alignement sur l’axe secondaire (trois enfants de hauteurs différentes).

flex-direction : le sens de l’axe principal.

flex-wrap : six éléments de 90 px, dans un parent trop étroit.

gap : l’espace entre les éléments.

Flexbox — attention et vérification

AvertissementAttention

display: flex se met sur le parent (le nav), pas sur les enfants (les liens). Sinon, rien ne bouge.

  • Vérifiez : quelle propriété pour centrer verticalement ?

Apport 2 — Grid (15 min)

  • Pourquoi : ranger des cartes en lignes et en colonnes.
  • Grid : un parent display: grid place ses enfants dans une grille.

Pourquoi. Une galerie de projets, une page avec en-tête, contenu et pied : il faut aligner dans les deux sens à la fois.

Définition. Grid organise en deux dimensions, lignes et colonnes (MDN Web Docs, s. d.-b, s. d.-d). grid-template-columns définit les colonnes ; 1fr est une fraction de l’espace disponible. Flexbox ou Grid ? Flexbox pour une rangée d’éléments (un menu, une liste de badges) ; Grid pour une grille à deux dimensions (des cartes, la page entière). Les deux se combinent : une grille de cartes, un menu en Flexbox.

Démonstration en direct, à ouvrir dans le navigateur : grid-template-columns sur six cartes. Elle se règle au clavier (Tab, puis les flèches) ou à la souris.

Exemple.

.projets {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 1rem;
}

Pas à pas.

  1. display: grid sur le conteneur des projets.
  2. grid-template-columns: repeat(3, 1fr) : trois colonnes égales.
  3. gap: 1rem : l’espace entre les cartes, dans les deux sens.
  4. F12 : cliquez sur le badge grid à côté de l’élément : la grille se dessine sur la page.

Apport — Mobile first (15 min)

  • Pourquoi : la majorité des visiteurs arrivent sur un téléphone.
  • Mobile first : les styles de base pour le téléphone, puis on enrichit.

Pourquoi. Commencer par le petit écran oblige à décider ce qui compte ; le grand écran ajoute de la place, pas de nouvelles idées.

Définition. En mobile first, les styles de base visent le téléphone (une seule colonne) ; une media query en min-width ajoute les styles des grands écrans (MDN Web Docs, s. d.-e). La balise meta name="viewport" de lundi est indispensable pour que le téléphone utilise sa vraie largeur (MDN Web Docs, s. d.-f).

Exemple.

.projets { display: grid; grid-template-columns: 1fr; }

@media (min-width: 48rem) {
  .projets { grid-template-columns: repeat(3, 1fr); }
}

Résultat : une page qui utilise ce code (un menu en Flexbox, trois projets en Grid, la media query min-width: 48rem), à trois largeurs.

Pas à pas.

  1. Écrivez la règle de base : une colonne.
  2. F12, mode responsive : réglez la largeur à 375 px ; une colonne.
  3. Ajoutez la media query ; élargissez à plus de 768 px (48 rem) : trois colonnes.

Mobile first — attention et vérification

AvertissementAttention

Une media query en max-width (héritée d’un tutoriel) inverse la logique : le téléphone reçoit des corrections au lieu des styles de base. Ici, toujours min-width.

  • Vérifiez : à 375 px, combien de colonnes dans l’exemple ?

Publier sur GitHub Pages (20 min)

  1. Un dépôt public à part, page-perso : dwwm-tp reste privé.
  2. git clone, puis copie de index.html et style.css ; git push.
  3. Settings → Pages → Deploy from a branch : main, / (root).
  4. Après deux minutes : pseudo.github.io/page-perso/.
  5. Réussi si : la page s’affiche, avec le cadenas (HTTPS).

Niveau : guidé.

AvertissementAttention

Un dépôt public est visible par tout le monde, et ses fichiers peuvent être copiés et indexés par les moteurs de recherche. Aucune donnée personnelle dedans : prénom ou pseudonyme, aucune adresse e-mail, aucun numéro de téléphone, aucune adresse postale. dwwm-tp reste privé : vous n’y changez rien.

GitHub Pages publie un site à partir d’un dépôt ; avec un compte gratuit, le dépôt doit être public (GitHub, s. d.-a). C’est pourquoi la page part dans un dépôt à part, page-perso, qui ne contient que les deux fichiers de la page.

  1. Sur GitHub, New repository : nom page-perso, Public, sans README.

  2. Dans Git Bash, en remplaçant pseudo par le vôtre :

    cd ~/dwwm
git clone git@github.com:pseudo/page-perso.git
cp dwwm-tp/semaine-05/page-perso/index.html dwwm-tp/semaine-05/page-perso/style.css page-perso/
cd page-perso
git add index.html style.css
git commit -m "Publie la page personnelle"
git push

    Vous devez voir : à la fin, * [new branch] main -> main ; sur GitHub, les deux fichiers dans page-perso.

  3. Puis Settings → Pages, comme sur la diapositive.

Vous continuez à travailler dans dwwm-tp/semaine-05/page-perso (les tests y sont). Pour mettre la page publiée à jour, refaites la copie (cp), puis git add, git commit et git push depuis ~/dwwm/page-perso. Les sites de projet ont une adresse de la forme https://<pseudo>.github.io/<dépôt> (GitHub, s. d.-c) et peuvent imposer HTTPS (GitHub, s. d.-b). La page n’est pas finie ? Publiez quand même : vous la corrigerez demain, après les audits, et chaque push met la page publiée à jour. Avant de pousser, relisez la page : prénom ou pseudonyme, aucune adresse e-mail en clair, formulaire annoncé comme non fonctionnel.
