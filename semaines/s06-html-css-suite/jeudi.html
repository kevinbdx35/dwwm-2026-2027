Jeudi 12/11 — Parcours d’autonomie, puis publier sa page

Formateur

Kevin Bardoux

Date de publication

jeudi 12 novembre 2026

Compétences visées : C3
Livrable : l’adresse HTTPS de votre page publiée, et node --test layout.test.js au vert.

ImportantLe minimum du jour
  • Le matin : les lignes 1 et 2 du parcours d’autonomie.
  • L’après-midi : la page personnelle publiée sur GitHub Pages, en HTTPS.
  • node --test layout.test.js au vert.

Le reste (rubrique « Si le temps le permet » et encadrés « Défi ») est la suite naturelle, pour ceux qui avancent.

Objectifs

  • Avancer seul dans un parcours, avec une méthode quand on bloque.
  • Publier une page sur GitHub Pages, depuis un dépôt public à part.
  • Mettre à jour la page publiée.

Comment se passe la journée. Le matin, vous travaillez en autonomie, sans le formateur : aucune notion nouvelle. L’après-midi, une notion : publier. Une démonstration, un pas à pas ensemble, puis vous mettez à jour votre page.

Matin — Autonomie, sans le formateur

Ce matin

  • Vous travaillez seul ou en binôme, sans le formateur.
  • Aucune notion nouvelle : vous suivez le parcours d’autonomie.
  • Notez vos questions : le formateur y répond à 12 h 45.
  • À 11 h 40 : enregistrez et envoyez votre travail.

Les horaires : 9 h 05, début ; 10 h 15 – 10 h 30, pause ; 11 h 00 – 11 h 05, ancrage ; 11 h 40, enregistrer et envoyer ; 11 h 45, fin de la matinée.

Le parcours d’autonomie

  • Onze lignes, dans l’ordre.
  • Pour chacune : un critère de réussite et un encadré « Aides ».
  • Si vous bloquez : la méthode, dans le support.
  • La liste complète est dans le support.

Ce parcours sert jeudi matin, puis vendredi après-midi au groupe B, et au soutien pair à pair de mardi prochain. Faites-le dans l’ordre, jusqu’où vous pouvez ; il n’y a pas de minimum à atteindre au-delà de la ligne 2.

Si l’on bloque, dans cet ordre :

  1. lisez le message d’erreur en entier ;
  2. cherchez-le dans la fiche Lire un message d’erreur ;
  3. relisez le pas à pas et copiez le dossier de rattrapage de l’étape où vous êtes bloqué ;
  4. demandez à CS50.ai une explication, pas le code ;
  5. demandez à un camarade, puis notez la question pour l’après-midi.

Preuve : un commit par exercice réussi dans dwwm-tp, puis git push en fin de demi-journée.

Adaptez le dossier et le message à ce que vous avez fait. Réussi si : git status affiche Votre branche est à jour avec 'origin/main' et rien à valider, la copie de travail est propre ; sur GitHub, le commit apparaît dans dwwm-tp. Après-midi — Publier sur GitHub Pages

Apport — Publier une page (15 min)

  • Pourquoi : montrer sa page à un employeur.
  • GitHub Pages : publie le contenu d’un dépôt à une adresse publique.

Pourquoi. Une page sur votre ordinateur n’existe que pour vous. Pour la montrer pendant votre recherche de stage, il faut la mettre en ligne.

Définition. GitHub Pages publie un site à partir d’un dépôt ; avec un compte gratuit, le dépôt doit être public (GitHub, s. d.-a). Les sites de projet ont une adresse de la forme https://<pseudo>.github.io/<dépôt> (GitHub, s. d.-c).

Le chemin d’un fichier : dwwm-tp (privé) → copie → page-perso (public) → git push → le site.

Exemple minimal. Un dépôt public qui contient index.html à sa racine : c’est tout ce qu’il faut.

Publier — attention et vérification

AvertissementAttention

GitHub Pages distingue les majuscules : Avatar.svg et avatar.svg sont deux fichiers. Sur votre ordinateur sous Windows, ça marche ; en ligne, l’image est absente (erreur 404). Écrivez les noms de fichiers à l’identique.

  • Vérifiez : pourquoi un dépôt à part, et non dwwm-tp ?

Pas à pas ensemble — Publier page-perso (1 h 10)

  1. Un dépôt public à part, page-perso : dwwm-tp reste privé.
  2. git clone, puis copie de index.html et style.css ; git push.
  3. Settings → Pages → Deploy from a branch : main, / (root).
  4. Après deux minutes : pseudo.github.io/page-perso/.
  5. Réussi si : la page s’affiche, avec le cadenas (HTTPS).

Niveau : guidé.

AvertissementAttention

Un dépôt public est visible par tout le monde, et ses fichiers peuvent être copiés et indexés par les moteurs de recherche. Aucune donnée personnelle dedans : prénom ou pseudonyme, aucune adresse e-mail, aucun numéro de téléphone, aucune adresse postale. dwwm-tp reste privé : vous n’y changez rien.

GitHub Pages publie un site à partir d’un dépôt ; avec un compte gratuit, le dépôt doit être public (GitHub, s. d.-a). C’est pourquoi la page part dans un dépôt à part, page-perso, qui ne contient que les deux fichiers de la page.

Les commentaires. Comme dans les pas à pas de lundi et mardi, tapez aussi les commentaires. Dans le terminal, un commentaire commence par # : Git Bash l’ignore. Sous macOS, le terminal (zsh) répond zsh: command not found: # ; tapez une fois setopt interactivecomments, et il les ignore aussi.

  1. Sur GitHub, New repository : nom page-perso, Public, sans README.

  2. Dans Git Bash, en remplaçant pseudo par le vôtre :

    # Terminal : aller dans le dossier dwwm
cd ~/dwwm
# Git : copier le dépôt public sur l'ordinateur
git clone git@github.com:pseudo/page-perso.git
# Terminal : copier la page dans le dépôt public
cp dwwm-tp/semaine-06/page-perso/index.html page-perso/
# Terminal : copier le style dans le dépôt public
cp dwwm-tp/semaine-06/page-perso/style.css page-perso/
# Terminal : entrer dans le dépôt public
cd page-perso
# Git : préparer les deux fichiers
git add index.html style.css
# Git : enregistrer une version, avec un message
git commit -m "Publie la page personnelle"
# Git : envoyer sur GitHub, qui publie la page
git push

    Vous devez voir : à la fin, * [new branch] main -> main ; sur GitHub, les deux fichiers dans page-perso.

  3. Sur GitHub, dans page-perso : Settings → Pages → Deploy from a branch : main, / (root), puis Save. Vous devez voir : après une à deux minutes, en haut de cette page, l’adresse de votre site.

  4. Ouvrez l’adresse https://pseudo.github.io/page-perso/. Vous devez voir : votre page, avec le cadenas (HTTPS).

Vous continuez à travailler dans dwwm-tp/semaine-06/page-perso (les tests y sont). Pour mettre la page publiée à jour, refaites la copie (cp), puis git add, git commit et git push depuis ~/dwwm/page-perso. Les sites de projet ont une adresse de la forme https://<pseudo>.github.io/<dépôt> (GitHub, s. d.-c) et peuvent imposer HTTPS (GitHub, s. d.-b). La page n’est pas finie ? Publiez quand même : vous la corrigerez demain matin, et chaque push met la page publiée à jour. Avant de pousser, relisez la page : prénom ou pseudonyme, aucune adresse e-mail en clair, formulaire annoncé comme non fonctionnel.

Mettre à jour la page publiée (30 min)

  1. Refaites la copie (cp) vers ~/dwwm/page-perso.
  2. git add, git commit, git push depuis ce dossier.
  3. Réussi si : après deux minutes, le site montre votre mise en page.

Niveau : guidé.

Depuis ~/dwwm :

# Terminal : copier la page dans le dépôt public
cp dwwm-tp/semaine-06/page-perso/index.html page-perso/
# Terminal : copier le style dans le dépôt public

# Git : enregistrer une version, avec un message

git push

Vous devez voir : après une à deux minutes, le site publié change. Vérifiez à 375 px et à 1280 px.
