Date de publication

Compétences visées : C4 · résolution de problème
Livrable : le pas à pas pas-a-pas-erreurs envoyé sur GitHub, et node --test g1-prix-invalide.test.js au vert.

ImportantLe minimum du jour

  • Le palier 1 : node --test g1-prix-invalide.test.js au vert, et le message d’erreur affiché dans la page.

Les paliers 2 et 3, puis la rubrique « Si le temps le permet », sont la suite naturelle, pour ceux qui avancent.

Objectifs

  • Signaler une saisie invalide en levant une erreur, avec throw.
  • Attraper cette erreur avec try / catch, et afficher son message dans la page.
  • Attraper de la même façon l’erreur d’une promesse attendue avec await.

Comment se passe la matinée. Une seule notion : gérer les erreurs. D’abord sans attente : une fonction de la logique vérifie une saisie et lève une erreur ; l’affichage l’attrape et écrit son message. Puis avec l’attente de mardi après-midi : un await sur une promesse rompue lève, lui aussi, une erreur, qu’on attrape de la même façon. Cet après-midi, vous en aurez besoin dès la première requête vers l’API.

Matin — Gérer les erreurs

Rappel (5 min)

  1. Que faut-il écrire devant une fonction qui contient await ?
  2. Un texte tapé par un visiteur : textContent ou innerHTML ?
  3. Que veut dire le code de statut HTTP 404 ?

Trois questions courtes, sans regarder vos notes : mardi, lundi, puis le mois passé. Répondez sur une feuille ; la correction suit, à l’oral.

Gérer les erreurs : throw, try / catch (20 min)

  • Pourquoi : une saisie invalide ne doit ni passer, ni tout arrêter.
  • throw new Error('…') : la fonction lève une erreur.
  • try essaie ; si une erreur est levée, catch l’attrape.
  • error.message : le texte à afficher dans la page.

Pourquoi. Jeudi dernier, vos fonctions de validation renvoyaient un message d’erreur, ou '' quand tout allait bien : celui qui appelle la fonction doit penser à regarder ce texte. Cette semaine, autre situation : une promesse peut ne pas être tenue, par exemple quand le musée demandé n’existe pas. Il faut une façon unique de dire « ça ne s’est pas passé comme prévu », et une façon unique de réagir, sans que la page reste bloquée.

Définition. throw new Error('message') lève une erreur : la fonction s’arrête à cette ligne et ne renvoie rien (MDN Web Docs, s. d.-d). Un bloc try { … } catch (error) { … } attrape l’erreur : dès qu’une ligne du try lève une erreur, les lignes suivantes du try sont sautées et le bloc catch s’exécute ; error.message contient le texte donné à new Error (MDN Web Docs, s. d.-e). Sans try, l’erreur arrête le programme.

L’erreur, de throw à catch, en image

Le texte du schéma : 1. dans le try, la ligne const id = checkId(text); lève une erreur (throw) ; 2. la ligne suivante du try, show(id);, est sautée ; 3. l’erreur arrive dans catch (error), qui affiche error.message ; 4. le programme continue : la page ne plante pas.

throw et try / catch, l’exemple minimal

Le premier programme de la notion, annoté : deux fichiers.

semaine-09/exemple/logic.js
export function parseCount(text) {
  const count = Number(text);
1  if (Number.isNaN(count)) {
2    throw new Error('Veuillez écrire un nombre de billets.');
  }
3  return count;
}
1
Le style défensif de la semaine 2 : on traite d’abord la saisie invalide.
2
throw lève une erreur, avec son message. La fonction s’arrête ici : elle ne renvoie rien.
3
Cette ligne ne s’exécute que si aucune erreur n’a été levée. 
semaine-09/exemple/app.js
1try {
2  const count = parseCount(field.value);
3  result.textContent = `${count} billets`;
4} catch (error) {
5  errorText.textContent = error.message;

1
try : « essaie ces lignes ».
2
Si parseCount lève une erreur, on quitte le try tout de suite.
3
Cette ligne est donc sautée quand la saisie est invalide.
4
catch reçoit l’erreur levée, rangée dans la variable error.
5

Avec await : la promesse rompue

  • Une promesse rompue, attendue avec await, lève une erreur.
  • Le même try / catch l’attrape.
  • loadMuseumOrFail('M9999') : « Musée introuvable : M9999 ».

Mardi, vos promesses étaient toujours tenues. Une promesse peut aussi être rompue : le serveur ne trouve pas ce qu’on lui demande, ou ne répond pas. Avec await, une promesse rompue se comporte comme un throw : la ligne lève une erreur, et le try / catch autour l’attrape (MDN Web Docs, s. d.-a). Cet après-midi, la fonction fournie loadMuseumOrFail(id) (fichier data/museum-db.js) tient sa promesse pour un identifiant connu, et la rompt pour un identifiant inconnu, avec l’erreur « Musée introuvable : M9999 ». Les données sont les 34 musées de Bretagne (Ministère de la Culture, s. d.).

Gérer les erreurs — attention et vérification

AvertissementAttention

Un catch vide (catch (error) { }) cache l’erreur : rien ne s’affiche, et personne ne sait pourquoi. Dans un catch, affichez toujours un message.

À l’inverse, une erreur levée sans try arrête le code en cours : dans le navigateur, la console affiche Uncaught Error, suivi de votre message (fiche « Lire un message d’erreur »).

  • La 1re ligne du try lève une erreur : et la 2e ?
  • Que contient error.message ?

Étape 1 — La logique lève une erreur. Dans logic.js, remplacez la ligne return text; de checkId par les lignes ci-dessous.

Avant d’exécuter : node essai.js affichera-t-il encore Fin ?

semaine-09/pas-a-pas-erreurs/logic.js
export function checkId(text) {
  // trim : le texte du champ, sans espaces autour
  const id = text.trim();
  // Champ vide : on lève une erreur, avec son message
  if (id === '') {
    // throw : la fonction s'arrête, l'erreur part
    throw new Error('Tapez un identifiant, par exemple M0194.');
  }
  // Mauvaise longueur : une autre erreur
  if (id.length !== 5) {
    // throw : la fonction s'arrête ici aussi
    throw new Error('Un identifiant a 5 caractères.');
  }
  // Tout va bien : on renvoie l'identifiant
  return id;
}

Enregistrez, puis lancez node essai.js.

Vous devez voir : Début, M0194, puis l’erreur, et pas de Fin : le programme s’est arrêté à la ligne du throw.

// submit : le bouton, ou la touche Entrée
form.addEventListener('submit', (event) => {

Étape 4 — La même chose, avec une attente. Trois changements dans app.js :

  1. En haut du fichier, la première ligne import est en commentaire : retirez ses deux barres //. Elle apporte loadMuseumOrFail.
  2. Ajoutez le mot async devant (event), avec son commentaire.
  3. Dans le try, remplacez la ligne result.textContent = … (et son commentaire) par les lignes ci-dessous ; dans le catch, ajoutez la ligne qui efface l’attente.

Avant d’exécuter : pour M9999, qui n’existe pas, quel bloc s’exécute : la fin du try, ou le catch ?

semaine-09/pas-a-pas-erreurs/app.js
// submit : le bouton, ou la touche Entrée
// async : la fonction contient un await
form.addEventListener('submit', async (event) => {
  // La page ne se recharge pas
  event.preventDefault();
  // On efface les anciens messages
  errorText.textContent = '';
  // Et l'ancien résultat
  result.textContent = '';
  // try : une erreur levée ici saute au catch
  try {
    // La logique vérifie : elle peut lever une erreur
    const id = checkId(field.value);
    // Le temps de la réponse : un message d'attente
    result.textContent = 'Recherche...';
    // await attend le musée ; promesse rompue : erreur levée
    const museum = await loadMuseumOrFail(id);
    // Trouvé : le nom et la ville
    result.textContent = `${museum.Nom_officiel} - ${museum.Ville}`;
  } catch (error) {
    // Le même catch pour les deux erreurs : on efface l'attente
    result.textContent = '';
    // Erreur attrapée : son message, dans la page
    errorText.textContent = error.message;
  }
});

Enregistrez.

Vous devez voir : avec M0194, « Recherche… », puis « musée de Dinan - Dinan » ; avec M9999, « Recherche… », puis « Musée introuvable : M9999 » en rouge ; sans rien écrire, « Tapez un identifiant, par exemple M0194. », tout de suite. Un seul catch pour les deux sortes d’erreurs.

Perdu ? Copiez rattrapage/erreurs/etape-4/app.js à la place de votre app.js.

  10. Rituel : un commit (git add g1-prix-invalide, git commit -m "Ajoute la solution de g1").

Réussi si : node --test g1-prix-invalide.test.js affiche ℹ fail 0 ; dans la page, 12.5 affiche « Prix du billet : 12.5 € », et abc affiche « Le prix doit être un nombre. » en rouge, sans erreur dans la console.

export async function museumLabelOrMessage(id) {
  try {

Pour aller plus loin. Avant les promesses, Node signalait une erreur asynchrone autrement : la fonction de rappel recevait l’erreur en premier paramètre (null quand tout allait bien), puis le résultat. Vous croiserez cette forme dans d’anciens exemples de code ; la documentation de Node la décrit, en anglais, sous le nom error-first callbacks (OpenJS Foundation, s. d.). Elle n’est pas au programme : avec async / await, le try / catch de cet après-midi suffit.
