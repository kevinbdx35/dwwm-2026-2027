Compétences visées : C4 · résolution de problème

ImportantLe minimum du jour

  • Le palier 1 : node --test p1-nom-du-musee.test.js au vert, et la page qui affiche « Chargement… », puis le musée.

Objectifs

  • Dire ce qu’est une promesse : une valeur qui arrive plus tard.
  • Recevoir cette valeur avec then.
  • Enchaîner deux then pour faire deux demandes à la suite.

Comment se passe la matinée. Une seule notion : la promesse. Hier après-midi, setTimeout vous a montré qu’un code peut s’exécuter plus tard. Ce matin, une fonction vous promet un résultat : un musée, demandé à un faux serveur qui met 300 millisecondes à répondre. Ce faux serveur est fourni (data/museum-db.js) : vous ne fabriquez pas de promesse, vous apprenez à en recevoir le résultat. Chaque exercice a la même page, déjà écrite : un bouton « Charger », un message, une liste.

Matin — Les promesses

Rappel (5 min)

  1. L’ordre : log('A'), setTimeout(() => log('B'), 0), log('C') ?
  2. Dans un formulaire, à quoi sert event.preventDefault() ?
  3. Quelle commande Git envoie vos commits sur GitHub ?

Trois questions courtes, sans regarder vos notes : la veille (lundi), la semaine passée, puis plus loin. Pour la première, log veut dire console.log : écrivez l’ordre des trois lettres. Répondez sur une feuille ; la correction suit, à l’oral.

La promesse et then (20 min)

  • Pourquoi : un serveur ne répond pas tout de suite.
  • Promesse : une valeur qui arrive plus tard.
  • then(fonction) : la fonction reçoit la valeur, à son arrivée.

Pourquoi. Une page demande ses données à un serveur : la liste des musées, par exemple. La réponse met du temps : quelques millisecondes, parfois plusieurs secondes. Si le navigateur attendait sans rien faire, la page serait figée : plus de clic, plus de défilement. JavaScript ne s’arrête donc pas : la fonction qui demande les données répond tout de suite, mais avec une promesse à la place des données.

Définition. Une promesse est un objet qui représente une valeur qui arrive plus tard. Elle est d’abord en attente ; quand la valeur arrive, elle est tenue (MDN Web Docs, s. d.-a). Pour utiliser la valeur, on donne une fonction à la promesse, avec then : cette fonction s’exécute à l’arrivée de la valeur, et la reçoit en paramètre (MDN Web Docs, s. d.-b). C’est un callback, comme la fonction donnée ce matin à setTimeout.

Une promesse peut aussi être rompue, quand la demande échoue : c’est le sujet de jeudi matin. Aujourd’hui, toutes les promesses sont tenues.

La promesse, en image

Le texte du schéma : 1. loadMuseum('M0207') renvoie tout de suite une promesse, en attente : pas encore de musée. 2. 300 millisecondes plus tard, le musée arrive : la promesse est tenue. 3. La fonction donnée à then s’exécute, avec le musée. En bas, l’erreur à éviter : status.textContent = loadMuseum('M0207'); affiche [object Promise] ; c’est dans la fonction de then que l’on reçoit le musée.

La promesse, l’exemple minimal

Le premier programme de la notion, annoté.

semaine-09/exemple/app.js
1import { loadMuseum } from '../data/museum-db.js';

2const promise = loadMuseum('M0194');
3promise.then((museum) => {
4  console.log(museum.Nom_officiel);
});
5console.log('Demande envoyée');
1
Déjà écrite dans vos fichiers : elle apporte loadMuseum, la fonction du faux serveur.
2
La demande part. loadMuseum renvoie tout de suite une promesse, en attente.
3
then : on donne une fonction à la promesse. Son paramètre, museum, recevra la valeur.
4
Cette ligne s’exécute 300 millisecondes plus tard, quand le musée est arrivé : musée de Dinan.
5
Cette ligne s’exécute avant la ligne 4 : JavaScript n’a pas attendu. La console affiche « Demande envoyée », puis « musée de Dinan ».

Enchaîner deux then

loadMuseum('M0194')
  .then((museum) => museum.Ville)
  .then((city) => console.log(city));
  • then renvoie une nouvelle promesse.
  • Sa valeur : ce que la fonction du then a renvoyé.

then renvoie lui-même une promesse : celle de la valeur renvoyée par sa fonction (MDN Web Docs, s. d.-b). Ici, le premier then reçoit le musée et renvoie sa ville ; le second then reçoit donc la ville, 'Dinan'. On écrit un then par ligne, l’un sous l’autre : c’est une chaîne. Si la fonction d’un then renvoie une promesse (une deuxième demande au serveur), le then suivant attend son résultat : c’est l’étape 3 du pas à pas.

La promesse — attention et vérification

AvertissementAttention

[object Promise] dans la page : vous avez affiché la promesse, pas sa valeur.

Dans la console, la même erreur s’écrit Promise {<pending>}. La valeur n’existe que dans la fonction donnée à then (fiche « Lire un message d’erreur »).

  • const m = loadMuseum('M0194'); : que vaut m.Ville ?
  • Où écrire la ligne qui affiche la ville ?

Pas à pas ensemble — Le musée qui arrive plus tard (35 min)

  • Le formateur code, vous tapez en même temps, une étape à la fois.
  • Code et commentaires : // au-dessus de chaque ligne.
  • Dossier : pas-a-pas-promesse : app.js, logic.js, essai.js.
  • Perdu ? Dossier rattrapage/promesse/, une étape à la fois.

Pas à pas, tous ensemble. Ouvrez le dossier pas-a-pas-promesse. La page (index.html, style.css) est déjà écrite : un bouton « Charger », un paragraphe #etat pour le message, une liste #liste. app.js commence par les lignes import et par trois sélections, déjà écrites : button, status et list. logic.js déclare une fonction, avec une ligne provisoire. Les données sont les 34 musées de Bretagne (Ministère de la Culture, s. d.) ; data/museum-db.js joue le serveur : ne le modifiez pas. Dans le terminal : cd pas-a-pas-promesse.

Avant de commencer. Ouvrez index.html avec Live Preview, puis la console (Ouvrir dans le navigateur, F12, onglet Console). Vous devez voir : le titre « Un musée et sa ville », le bouton « Charger », et rien d’autre ; un clic ne fait rien. Dans la console, une ligne qui commence par « Prêt » : elle vient de la dernière ligne d’app.js, que vous supprimerez à l’étape 4.

Étape 1 — Demander, et regarder ce qu’on reçoit. Dans app.js, au-dessus de la ligne console.log('Prêt', …);, écrivez l’écouteur du bouton.

Avant d’exécuter : après un clic, que va afficher la console ?

semaine-09/pas-a-pas-promesse/app.js
// Au clic sur le bouton Charger
button.addEventListener('click', () => {
  // Le message d'attente, tout de suite
  status.textContent = 'Chargement...';
  // La demande part : on reçoit une promesse, pas le musée
  const promise = loadMuseum('M0207');
  // Dans la console : la promesse, encore en attente
  console.log(promise);
});

Enregistrez, puis cliquez sur « Charger ».

Vous devez voir : dans la page, « Chargement… », qui ne change plus ; dans la console, Promise {<pending>} : la promesse, en attente. Le musée n’est affiché nulle part : on ne l’a pas encore demandé à la promesse.

Perdu ? Copiez rattrapage/promesse/etape-1/app.js à la place de votre app.js, puis repartez avec le groupe.

Étape 2 — then : quand le musée arrive. Dans l’écouteur, sous la ligne console.log(promise);, ajoutez :

Avant d’exécuter : « Chargement… » va-t-il rester à l’écran ?

semaine-09/pas-a-pas-promesse/app.js
  // then : la fonction donnée s'exécutera à l'arrivée
  promise.then((museum) => {
    // Le musée est arrivé : son nom remplace le message
    status.textContent = museum.Nom_officiel;
  });

Enregistrez, puis cliquez sur « Charger ».

Vous devez voir : « Chargement… » pendant un instant, puis « musée des beaux-arts ».

Perdu ? Copiez rattrapage/promesse/etape-2/app.js à la place de votre app.js.

Étape 3 — La logique : deux demandes à la suite. Dans logic.js, remplacez la ligne provisoire de cityMuseumNames par la chaîne ci-dessous. La fonction renvoie une promesse : celle des noms des musées de la même ville.

Avant d’exécuter : combien de noms va afficher node essai.js ?

semaine-09/pas-a-pas-promesse/logic.js
export function cityMuseumNames(id) {
  // Première demande : le musée qui a cet identifiant
  return loadMuseum(id)
    // then 1 : il arrive, on demande ceux de sa ville
    .then((museum) => loadMuseumsOfCity(museum.Ville))
    // then 2 : la liste arrive, on garde les noms
    .then((museums) => museums.map((item) => item.Nom_officiel));
}

Enregistrez, puis lancez node essai.js dans le terminal, depuis pas-a-pas-promesse.

Vous devez voir : [ 'musée des beaux-arts', 'musée départemental breton' ] : les deux musées de Quimper, sans aucun navigateur. La fonction du premier then renvoie une promesse (la deuxième demande) : le second then a attendu son résultat.

Perdu ? Copiez rattrapage/promesse/etape-3/logic.js à la place de votre logic.js.

Étape 4 — L’affichage : la liste. Dans app.js, dans l’écouteur, sous le then de l’étape 2, ajoutez :

Avant d’exécuter : qu’est-ce qui s’affiche en premier, le nom ou la liste ?

semaine-09/pas-a-pas-promesse/app.js
  // On vide la liste avant de la remplir
  list.textContent = '';
  // La logique renvoie une promesse : les noms de la ville
  cityMuseumNames('M0207').then((names) => {
    // for...of : un <li> par nom reçu
    for (const name of names) {
      // Un nouveau <li>
      const item = document.createElement('li');
      // Son texte : le nom du musée
      item.textContent = name;
      // Ajouté à la fin de la liste
      list.append(item);
    }
  });

Supprimez aussi, en bas du fichier, les deux commentaires et la ligne console.log('Prêt', …); : tout est maintenant utilisé. Enregistrez, puis cliquez sur « Charger ».

Vous devez voir : « Chargement… », puis « musée des beaux-arts », puis la liste : « musée des beaux-arts » et « musée départemental breton ». Le nom arrive avant la liste : une demande pour le nom, deux demandes à la suite pour la liste. Un deuxième clic affiche toujours deux lignes, pas quatre.

Perdu ? Copiez rattrapage/promesse/etape-4/app.js à la place de votre app.js.

Exercices — Les promesses

// logic.js
export function neighbourNames(id) {
  return loadMuseum(id)

Pour aller plus loin

Quand une promesse est tenue, la fonction de son then ne s’exécute pas tout de suite : elle attend que le code en cours soit terminé, puis passe avant les minuteurs de setTimeout. Cette file prioritaire est celle des microtâches. Le guide Utiliser les promesses de MDN, en français, l’explique dans sa partie sur le minutage (MDN Web Docs, s. d.-c). Ce n’est pas au programme de l’évaluation.
