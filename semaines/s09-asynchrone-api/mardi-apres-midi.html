Mardi 01/12, après-midi — async / await

Date de publication

mardi 1 décembre 2026

Compétences visées : C4 · résolution de problème
Livrable : le pas à pas pas-a-pas-async envoyé sur GitHub, et node --test a1-attendre-un-musee.test.js au vert.

ImportantLe minimum du jour
  • Le pas à pas « La même page, sans then », fait avec le groupe.
  • Le palier 1 : node --test a1-attendre-un-musee.test.js au vert, et « Le musée M0194 est à Dinan » affiché dans le navigateur.

Les paliers 2 et 3, puis la rubrique « Si le temps le permet », sont la suite naturelle, pour ceux qui avancent.

Objectifs

  • Écrire une fonction async qui attend une promesse avec await.
  • Réécrire avec async et await un code écrit avec then.
  • Reconnaître un await oublié, et un await écrit hors d’une fonction async.

Comment se passe l’après-midi. Une seule notion : async / await. Ce matin, vous receviez une valeur « plus tard » avec then. Cet après-midi, vous écrivez la même chose autrement : les lignes l’une sous l’autre, comme un code ordinaire. Les fonctions qui renvoient une promesse sont toujours fournies (data/museum-db.js), et elles réussissent toujours : les erreurs sont le sujet de cet après-midi.

Après-midi — async / await

async et await (15 min)

  • Pourquoi : écrire les étapes l’une sous l’autre, sans then.
  • await attend une promesse et donne sa valeur.
  • async : la fonction a le droit d’attendre ; elle renvoie une promesse.

Pourquoi. Avec then, la suite du programme est rangée dans une fonction, puis dans une autre : dès qu’il y a deux attentes, le code se décale vers la droite et se lit mal. Avec await, chaque étape tient sur une ligne, et le résultat se range dans une constante, comme d’habitude.

Définition. await, écrit devant une promesse, attend qu’elle soit tenue, puis donne sa valeur. Il ne s’écrit que dans une fonction déclarée avec async. Une fonction async renvoie toujours une promesse, tenue avec la valeur de son return (MDN Web Docs, s. d.-a, s. d.-b).

await, en image

Le texte du schéma : la fonction showMuseum a trois lignes. La première s’exécute tout de suite. À la deuxième, await met la fonction en pause : pendant ce temps, la page reste libre (clics, défilement, autres fonctions). Quand la promesse est tenue, environ 300 millisecondes plus tard, la fonction reprend à la ligne suivante. await met la fonction en pause, pas la page.

async et await, l’exemple minimal

Le premier programme de la notion, annoté. Les données sont les 34 musées de Bretagne du dossier data (Ministère de la Culture, s. d.).

semaine-09/exemple/app.js
1import { loadMuseum } from '../data/museum-db.js';

2async function showMuseum() {
3  message.textContent = 'Chargement...';
4  const museum = await loadMuseum('M0194');
5  message.textContent = museum.Nom_officiel;
}
1
Déjà écrite : elle apporte loadMuseum, qui renvoie une promesse et répond après 300 millisecondes.
2
async : cette fonction a le droit d’attendre.
3
Cette ligne s’exécute tout de suite, avant la réponse.
4
await : la fonction se met en pause ici. Quand la promesse est tenue, le musée est rangé dans museum.
5
La suite : museum est un vrai musée, avec ses champs.

async et await — attention et vérification

AvertissementAttention

SyntaxError: Unexpected reserved word : vous avez écrit await dans une fonction qui n’est pas async. Ajoutez async devant function (fiche « Lire un message d’erreur »).

  • Vérifiez : que renvoie une fonction async qui fait return 42 ?
  • À quelle ligne la fonction se met-elle en pause ?

Avant/après, pour reconnaître l’erreur :

// Avant : la console affiche Unexpected reserved word
function showMuseum() {
  const museum = await loadMuseum('M0194');
}
// Après : async devant function
async function showMuseum() {
  const museum = await loadMuseum('M0194');
}

Pas à pas ensemble — La même page, sans then (30 min)

  • Le formateur code, vous tapez en même temps, une étape à la fois.
  • Code et commentaires : // au-dessus de chaque ligne.
  • Dossier : pas-a-pas-async : app.js, logic.js, essai.js.
  • Perdu ? Dossier rattrapage/async/, une étape à la fois.

Pas à pas, tous ensemble. Ouvrez le dossier pas-a-pas-async. La page marche déjà : elle est écrite avec then, comme ce matin. Vous allez la réécrire avec async et await, sans changer ce qu’elle affiche. Dans le terminal : cd pas-a-pas-async.

Avant de commencer. Ouvrez index.html avec Live Preview, puis cliquez sur « Charger ». Vous devez voir : « Chargement… », puis « musée de Dinan - Dinan », et une ligne « Le musée M0199 est à Concarneau ».

Étape 1 — Une attente : await à la place de then. Dans app.js, remplacez toute la fonction showMuseum (et son commentaire « Étape 1 ») par celle-ci.

Avant d’exécuter : la page va-t-elle afficher autre chose qu’avant ?

semaine-09/pas-a-pas-async/app.js
// async : cette fonction a le droit d'attendre
async function showMuseum() {
  // Affiché tout de suite, avant la réponse
  message.textContent = 'Chargement...';
  // await : la fonction attend ici le musée
  const museum = await loadMuseum('M0194');
  // La suite s'exécute quand le musée est arrivé
  message.textContent = `${museum.Nom_officiel} - ${museum.Ville}`;
}

Enregistrez, puis cliquez sur « Charger ».

Vous devez voir : exactement comme avant, « Chargement… », puis « musée de Dinan - Dinan ». Le code a changé, pas la page.

Perdu ? Copiez rattrapage/async/etape-1/app.js à la place de votre app.js, puis repartez avec le groupe.

Étape 2 — La logique : une fonction async renvoie une promesse. Dans logic.js, remplacez toute la fonction cityOf (et son commentaire « Étape 2 ») par celle-ci.

Avant d’exécuter : essai.js appelle cityOf('M0199').then(…). Ce then marchera-t-il encore ?

semaine-09/pas-a-pas-async/logic.js
// async : cityOf renvoie toujours une promesse
export async function cityOf(id) {
  // await : on attend le musée demandé
  const museum = await loadMuseum(id);
  // return : la promesse de cityOf donne la ville
  return museum.Ville;
}

Enregistrez, puis lancez node essai.js dans le terminal, depuis pas-a-pas-async.

Vous devez voir : Concarneau. Le then d’essai.js marche toujours : une fonction async renvoie une promesse, comme les fonctions de ce matin.

Perdu ? Copiez rattrapage/async/etape-2/logic.js à la place de votre logic.js.

Étape 3 — Deux attentes à la suite. Dans app.js, remplacez toute la fonction showCities (et son commentaire « Étape 3 ») par celle-ci.

Avant d’exécuter : les deux lignes de la liste vont-elles apparaître en même temps ?

semaine-09/pas-a-pas-async/app.js
// async : cette fonction a le droit d'attendre
async function showCities() {
  // On vide la liste avant de la remplir
  list.textContent = '';
  // Première attente : la ville du musée M0199
  const first = await cityOf('M0199');
  // Une ligne de plus dans la liste
  addLine(`Le musée M0199 est à ${first}`);
  // Deuxième attente : elle commence après la première
  const second = await cityOf('M0207');
  // Une deuxième ligne, un instant plus tard
  addLine(`Le musée M0207 est à ${second}`);
}

Enregistrez, puis cliquez sur « Charger ».

Vous devez voir : « Le musée M0199 est à Concarneau », puis, un instant plus tard, « Le musée M0207 est à Quimper ». Les deux attentes se suivent : la deuxième ne commence que quand la première est finie.

Perdu ? Copiez rattrapage/async/etape-3/app.js à la place de votre app.js.

Variante à faire seuls

AstuceIndice 1 — l’idée

Chaque promesse.then((valeur) => { suite }) devient deux choses : const valeur = await promesse;, puis la suite, écrite en dessous, sans fonction autour. Et la fonction qui contient ce await prend le mot async. Un then dans un then : deux await, l’un sous l’autre.

AstuceIndice 2 — le squelette 
// logic.js — museumLabel(id), avec async devant function :
//   attendre loadMuseum(id), ranger le musée dans une constante
//   renvoyer le texte « nom - ville »

// logic.js — twoCities(idA, idB), avec async devant function :
//   attendre le premier musée, puis attendre le second
//   renvoyer le texte « ville et ville »

// app.js — show, avec async devant function :
//   « Chargement... », la liste vidée (ces deux lignes ne changent pas)
//   attendre museumLabel('M0194'), l'écrire dans le message
//   attendre twoCities('M0199', 'M0207'), l'ajouter dans un <li>
AstuceIndice 3 — la solution, moins une ligne 
// logic.js
export async function museumLabel(id) {
  const museum = await loadMuseum(id);
  return `${museum.Nom_officiel} - ${museum.Ville}`;
}

export async function twoCities(idA, idB) {
  const first = await loadMuseum(idA);
  // Il manque une ligne : la deuxième attente.
  return `${first.Ville} et ${second.Ville}`;
}

// app.js : show suit le même modèle, avec deux await.

Dans le pas à pas, deux attentes à la suite prenaient deux fois plus de temps qu’une seule. Dans a4-tous-ensemble/logic.js, namesOf(ids) reçoit un tableau d’identifiants et renvoie, plus tard, le tableau des noms des musées, dans le même ordre. Les musées sont demandés tous ensemble : quatre musées arrivent en 300 millisecondes environ, et non en 1 200. Cherchez dans la documentation comment attendre plusieurs promesses à la fois : Promise.all (MDN Web Docs, s. d.-c).
