Après-midi — fetch et response.ok

fetch et response.ok (15 min)

  • Pourquoi : les données sont sur un serveur.
  • fetch(adresse) envoie une requête ; await attend la réponse.
  • response.ok : true si le statut va de 200 à 299.
  • response.json() : la réponse, en objets JavaScript.

Pourquoi. Depuis la semaine 8, vos pages lisent une copie des musées, rangée dans un fichier du dossier data. Une copie vieillit : si un musée ouvre demain, elle ne le saura pas. Les vraies données sont sur un serveur, qui les donne à qui les demande : c’est une API. Il faut donc envoyer une requête HTTP depuis JavaScript, attendre la réponse, et vérifier qu’elle est bonne.

Définition. fetch(adresse) envoie une requête à cette adresse et renvoie une promesse : avec await, on obtient la réponse du serveur (MDN Web Docs, s. d.-e). La réponse porte un code de statut (response.status) ; response.ok vaut true quand ce code va de 200 à 299, false sinon (MDN Web Docs, s. d.-c). await response.json() transforme la réponse en objets JavaScript (MDN Web Docs, s. d.-b).

Le point à retenir : un 404 ou un 500 est une réponse comme une autre. fetch ne lève pas d’erreur dans ce cas. C’est vous qui la levez, avec throw, quand response.ok vaut false.

fetch et response.ok, en image

Le texte du schéma : await fetch(adresse) envoie une requête au serveur, qui renvoie une réponse avec son code de statut. Puis une question : response.ok ? Oui (200 à 299) : await response.json() donne les données. Non (404, 500…) : fetch ne lève pas d’erreur ; vous écrivez throw new Error(…), le catch l’attrape, et la page affiche un message.

fetch et response.ok, l’exemple minimal

Le premier programme de la notion, annoté : les numéros renvoient aux explications sous le code.

semaine-09/exemple/logic.js
1export async function loadMuseums() {
2  const response = await fetch('../data/musees-bretagne.json');
3  if (!response.ok) {
4    throw new Error(`Réponse du serveur : ${response.status}`);
  }
5  const result = await response.json();
6  return result.data;
}
1
async : la fonction contient des await, et renvoie une promesse (mardi après-midi).
2
fetch envoie la requête ; await attend la réponse du serveur.
3
!response.ok : « la réponse n’est pas bonne » (un 404, un 500…).
4
On lève une erreur, avec le statut dans son message (jeudi matin) : la fonction s’arrête là.
5
json() transforme la réponse en objets JavaScript ; il faut l’attendre aussi.
6
Dans cette réponse, le tableau des musées est rangé dans le champ data.

fetch et response.ok — attention et vérification

AvertissementAttention

Unexpected token '<', "<!DOCTYPE "... is not valid JSON : le serveur a répondu par une page d’erreur (un 404), et votre code l’a lue comme des données. Vérifiez response.ok avant response.json() (fiche « Lire un message d’erreur »).

  • Vérifiez : le fichier demandé n’existe pas. Que vaut response.ok ?
  • Le catch s’exécute-t-il tout seul ?

Étape 3 — Un fichier absent. Dans l’adresse, retirez le e de bretagne : '../data/musees-bretagn.json'. Enregistrez.

Avant d’exécuter la suite : la console affiche une erreur. À quelle ligne de votre code ?

Vous devez voir, dans la console : 404 false, puis, en rouge, Uncaught (in promise) SyntaxError: Unexpected token '<', "<!DOCTYPE "... is not valid JSON. La page affiche « 0 musées », sans rien dire au visiteur.

Remplacez maintenant toute la fonction start par celle-ci : les lignes que vous avez déjà tapées sont rangées dans un try.

semaine-09/pas-a-pas-fetch/app.js
// async : cette fonction peut attendre (await)
async function start() {
  // try : on essaie ; une erreur fait sauter au catch
  try {
    // fetch demande l'adresse ; await attend la réponse
    const response = await fetch('../data/musees-bretagn.json');
    // status : le code de statut ; ok : true de 200 à 299
    console.log(response.status, response.ok);
    // Pas ok (404, 500...) : on lève une erreur
    if (!response.ok) {
      // Le message de l'erreur contient le statut
      throw new Error(`Réponse du serveur : ${response.status}`);
    }
    // json() transforme la réponse en objets JavaScript
    const result = await response.json();
    // data : le tableau des musées, dans la réponse
    showList(result.data);
  } catch (error) {
    // Le paragraphe du message, caché au départ
    const message = document.querySelector('#message');
    // Le message pour le visiteur, avec la cause
    message.textContent = `Chargement impossible. ${error.message}`;
    // hidden à false : le paragraphe devient visible
    message.hidden = false;
  }
}

Enregistrez.

Vous devez voir, dans la page, en rouge : « Chargement impossible. Réponse du serveur : 404 ». Dans la console : 404 false, et plus d’erreur SyntaxError.

Remettez le e : '../data/musees-bretagne.json'. Enregistrez. Vous devez voir : de nouveau « 34 musées » et la liste, sans message.

Avant d’exécuter : si le serveur répond 404, quelle ligne s’exécute en dernier ?

explorateur-musees/loading.js
export async function loadMuseums(url) {
  // fetch : la requête part ; await attend la réponse
  const response = await fetch(url);
  // response.ok est faux pour un 404 ou un 500
  if (!response.ok) {
    // throw : l'erreur remonte jusqu'à un catch
    throw new Error(`Le serveur a répondu ${response.status}`);
  }
  // json() transforme la réponse en objets JavaScript
  const answer = await response.json();
  // Le tableau des musées est dans la propriété data
  return answer.data;
}
