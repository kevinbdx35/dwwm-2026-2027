Groupe A : projet & consolidation

Groupe A en formation de 12 h 45 à 17 h ; le groupe B est au sport (13 h 15 – 16 h).
Pas de notion nouvelle : on termine, on consolide, on avance dans le projet, en binôme.

Au programme

  1. Terminer : les paliers 1 de la semaine.
  2. Le projet, en binôme : finir US-4, US-2 ou US-3, puis relire.
  3. Pour ceux qui avancent : les favoris du projet (palier 3).
  4. Le défi de la semaine : le musée du jour, à rendre mardi 08/12.
  5. Ensuite : le parcours d’autonomie.

Aucune notion nouvelle : la faille XSS, setTimeout, les promesses, async / await, throw et try / catch, fetch, JSON et localStorage ont été vus cette semaine. Rien de ce qui se fait cet après-midi n’est nécessaire pour lundi : le groupe B, au sport, n’aura rien à rattraper.

Terminer, seul (30 min) : les paliers 1 de la semaine que vous n’avez pas validés (ils passent avant le défi), dans l’ordre des jours, avec leur entraînement si le palier 1 vous a demandé de l’aide ou la correction. La liste des exercices est dans la fiche de révision.

Le projet n° 1, en binôme (1 h 30). Il passe avant le défi. Le travail en binôme est obligatoire sur les créneaux du projet ; les binômes sont formés à l’intérieur du groupe A.

Binôme : ______

Les rôles sont ceux de mercredi après-midi :

  1. Le pilote tape. Il dit à voix haute ce qu’il écrit. Il ne tape rien que le copilote n’a pas compris.
  2. Le copilote ne touche pas au clavier. Il lit la consigne, dit quoi faire, relit chaque ligne tapée.
  3. Toutes les 20 minutes (minuteur), échangez les rôles.
  4. Travaillez d’abord sur le dépôt de l’un, puis refaites le travail sur le dépôt de l’autre.
  5. Chaque Pull Request : son auteur la relit avec la grille ; son binôme la relit avec la même grille et écrit un commentaire dans la Pull Request ; son auteur la fusionne.

Dans un trinôme, la troisième personne tient le minuteur et la grille de relecture ; les trois rôles tournent toutes les 20 minutes.

Dans cet ordre, sur chacun des deux dépôts explorateur-musees :

  1. US-4, les musées viennent de l’API : terminez ce qui reste du pas à pas de jeudi après-midi, puis US-2 ou US-3 si elle n’est pas fusionnée. Réussi si : la Pull Request est relue par le binôme et fusionnée.
  2. La relecture croisée de US-4 : chacun relit la Pull Request US-4 de son binôme avec la grille et y écrit un commentaire (une Pull Request fusionnée se commente aussi). US-5 (les états « erreur » et « vide ») se fait avec tout le groupe en semaine 10 : ne la commencez pas.
  3. Les favoris (palier 3 de ce matin), pour ceux qui avancent : une branche favoris, la logique testée, les favoris gardés dans localStorage.

Réussi si : sur chaque dépôt, chaque histoire terminée a sa Pull Request, avec un commentaire de relecture du binôme, fusionnée par son auteur.

Le défi de la semaine, seul (1 h 30) : le palier 1 (45 min), puis le palier 2 (45 min) ; le palier 3 pour ceux qui ont fini. À rendre mardi 08/12 avant 15 h 30 : le lien de votre dernier commit du défi dans dwwm-tp (sur GitHub, ouvrez le commit, copiez l’adresse de la page), envoyé au formateur. Rendez ce que vous avez fait cet après-midi : le travail à la maison n’est jamais obligatoire. Mardi 08/12, de 15 h 30 à 17 h, le groupe A corrige le défi ensemble, avec le formateur.

Ensuite, seul : le parcours d’autonomie, là où vous en êtes, puis les paliers 2 et 3 de la semaine non terminés.

Défi de la semaine : le musée du jour

  • Une maquette à reproduire : une carte, puis une fiche.
  • Tout est fourni : textes, images, police, guide de style.
  • Dossier defi-01-musee-du-jour, dans l’archive de la semaine.
  • À rendre mardi 08/12 : le lien de votre commit.

Le principe. Dans une entreprise, l’intégrateur reçoit une maquette (l’image de la page attendue), un guide de style (les couleurs, la police, les tailles) et les textes. Il écrit le HTML et le CSS qui donnent la même page, sur un téléphone comme sur un ordinateur. Chaque semaine, un nouveau défi vous entraîne à ce métier, avec des notions déjà vues seulement. Celui-ci : HTML, CSS (S5, S6), position (R1, R2), :hover et :focus-visible (R4), object-fit (R6), le DOM et les événements (S8), throw (jeudi).

Le dossier. Il est dans l’archive de la semaine, déjà extraite dans semaine-09 : defi-01-musee-du-jour/. Ouvrez d’abord README.md (les user stories et la liste de contrôle), puis guide-de-style.md et contenu.md. Le musée, les villes et les autres musées sont inventés pour le cours.

La liste de contrôle, pour chaque palier, avant de dire « fini » :

  1. Vous devez voir : votre page ressemble à la maquette, à 375 px et à 1280 px (outils du navigateur, mode appareil).
  2. Le validateur du W3C : collez votre HTML dans l’onglet Validate by Direct Input : aucune erreur.
  3. WAVE : aucune erreur, aucune erreur de contraste.
  4. Lighthouse, catégorie Accessibilité : 90 ou plus.
  5. Au clavier : avec Tab, chaque lien a un contour bien visible.

Palier 1 — La carte du musée

  1. Étape 1 : le HTML de la carte, dans carte.html.
  2. Étape 2 : la police, les variables, la page.
  3. Étapes 3 à 5 : la carte, l’image, le texte.
  4. Étape 6 : le badge sur l’image (R1).
  5. Étape 7 : le lien, au survol et au clavier (R4).

Palier 1 : guidé. Durée indicative : 45 min. Dossier defi-01-musee-du-jour, fichiers carte.html et style.css. Vous tapez le code et ses commentaires, une étape à la fois. En HTML, un commentaire s’écrit <!-- … --> ; en CSS, /* … */.

La maquette. Votre carte doit ressembler à celle-ci, au survol de la souris (à gauche) et au focus du clavier (à droite) :

Avant de commencer. Ouvrez defi-01-musee-du-jour/carte.html avec Live Preview, puis Ouvrir dans le navigateur. Vous devez voir : le titre « Le musée du jour », en police du système, sur un fond blanc.

Étape 1 — Le HTML de la carte. Dans carte.html, à la place de la ligne de commentaire « Palier 1, étape 1 », tapez la carte. Les textes viennent de contenu.md.

<!-- La carte : un article, un musée -->
<article class="carte">

    <!-- Le badge, posé sur l'image à l'étape 6 -->

  </div>
  <!-- Le bas de la carte : le texte -->
  <div class="carte-texte">
    <!-- Le nom du musée -->
    <h2 class="carte-titre">Musée de la carte postale</h2>
    <!-- La ville -->
    <p class="carte-ville">Port-Morvan</p>

Enregistrez, puis rechargez la page du navigateur.

Vous devez voir : la photo de la maison, très grande, puis « Gratuit le dimanche », le nom du musée, la ville, la phrase et le lien souligné. Rien n’est encore mis en forme : c’est le travail du CSS.

Perdu ? Copiez rattrapage/defi-01-carte/etape-1/carte.html à la place de votre carte.html.

/* La même police, en gras */

/* Les couleurs et les espaces du guide de style */

  font-family: "Atkinson", sans-serif;

  line-height: 1.5;

  /* Pas de marge autour de la page */
  margin: 0;
}

/* Le contenu : de l'espace sur les bords */
main {
  /* L'espace intérieur */
  padding: var(--espace-moyen);
}

Enregistrez, puis rechargez.

Vous devez voir : le fond couleur papier, et tout le texte dans la police Atkinson Hyperlegible : regardez le zéro de « 20 000 », barré d’un trait. Si le zéro n’est pas barré, la police n’est pas chargée : vérifiez le chemin fonts/… et son orthographe.

Perdu ? Copiez rattrapage/defi-01-carte/etape-2/style.css à la place de votre style.css.

Étape 6 — Le badge sur l’image (R1). Le badge sort du flux et se pose sur l’image. Son repère est le haut de la carte, .carte-image. Sous la règle .carte-ville :

Avant d’enregistrer : sans la règle .carte-image, où irait le badge ?

semaine-09/defi-01-musee-du-jour/style.css
/* Le repère du badge : le haut de la carte */
.carte-image {
  /* relative : l'enfant en absolute se place ici */
  position: relative;
}

/* Le badge, posé sur l'image */
.badge {
  /* absolute : sorti du flux, placé dans le repère */
  position: absolute;
  /* Placé à 12 px du haut */
  top: 0.75rem;
  /* Placé à 12 px de la gauche */
  left: 0.75rem;
  /* Pas de marge : un paragraphe en a une */
  margin: 0;
  /* L'espace intérieur du badge */
  padding: 0.25rem 0.75rem;
  /* Le fond jaune */
  background: var(--couleur-soleil);
  /* Des bords tout ronds */
  border-radius: 999px;
  /* Le texte en gras */
  font-weight: 700;
  /* Le texte un peu plus petit : 14 px */
  font-size: 0.875rem;
}

Vous devez voir : le badge jaune « Gratuit le dimanche », en gras, posé en haut à gauche de l’image ; le texte de la carte est remonté sous l’image. Sans position: relative sur .carte-image, le badge se placerait par rapport à la page entière : en haut à gauche de l’écran.

Perdu ? Copiez rattrapage/defi-01-carte/etape-6/style.css.

Étape 7 — Le lien, à la souris et au clavier (R4). Sous la règle .badge :

}

Palier 2 — La fiche du musée

  1. Créez index.html : en-tête, trois sections, pied de page.
  2. Textes et images : contenu.md, images/.
  3. style.css : en-tête collé en haut (R2), grilles.
  4. Mobile first : 1 colonne, puis 3 à partir de 48rem.
  5. Réussi si : la page ressemble à la maquette.

Palier 2 : recommandé, semi-guidé. Durée indicative : 45 min ; ce qui n’est pas fini se termine dans le parcours d’autonomie. Vous écrivez deux fichiers sur trois : index.html, que vous créez, et la suite de style.css. Les règles du palier 1 servent telles quelles : les cartes des autres musées sont les mêmes que celle du palier 1.

  1. Dans defi-01-musee-du-jour, créez index.html, avec la même tête que carte.html et le titre « Musée de la carte postale - Musées de Bretagne ».
  2. Dans body, écrivez trois parties : un header (le nom du site, puis un nav avec les trois liens du menu), un main, un footer (les deux phrases du pied de page).

Écrivez tout le HTML d’abord, sans style. Dans le bloc « Horaires » de la fiche, le visiteur choisit un jour dans une liste ; la page lui dit si le musée est ouvert ce jour-là.
