Objectifs

  • Programmer l’exécution d’une fonction plus tard, avec setTimeout.
  • Prédire l’ordre dans lequel s’exécutent des lignes de code qui contiennent un setTimeout.
  • Afficher un message d’attente, puis un résultat qui arrive plus tard.

Comment se passe l’après-midi. Ce matin, la faille XSS, reportée du vendredi 27/11. Cet après-midi, une seule notion : setTimeout et l’ordre d’exécution. Jusqu’ici, votre code s’exécutait de haut en bas, une ligne après l’autre. Cette semaine, certaines choses arrivent plus tard : la réponse d’un serveur, par exemple. Ce code qui s’exécute plus tard s’appelle du code asynchrone. Cet après-midi, nous le découvrons avec l’outil le plus simple : un minuteur. D’abord une démonstration lente, puis nous codons ensemble, une étape à la fois, puis vos exercices, en trois paliers.

Les exercices de la semaine. Comme en semaine 8, chaque exercice est une petite page : logic.js calcule, et les tests le vérifient ; app.js affiche, et vous le vérifiez dans le navigateur. Trois paliers : le palier 1 est le minimum, guidé ; le palier 2 est recommandé, semi-guidé ; le palier 3 est autonome. Tous les exercices d’une même demi-journée partent de la même page.

setTimeout (15 min)

  • Pourquoi : une réponse qui arrive plus tard.
  • setTimeout(fonction, délai) : « exécute-la plus tard ».
  • Le délai est en millisecondes : 2000 = 2 secondes.
  • En attendant, le reste du code continue.

Pourquoi. Quand une page demande des données à un serveur, la réponse n’arrive pas tout de suite : une demi-seconde, parfois trois. Pendant ce temps, le visiteur doit voir « Chargement… », et la page doit continuer à répondre. Il faut donc savoir écrire du code qui s’exécutera plus tard, et savoir dans quel ordre tout cela se passe. Jeudi, c’est le vrai serveur de Muséofile qui répondra plus tard ; cet après-midi, un minuteur de 2 secondes joue son rôle.

Définition. setTimeout(fonction, délai) demande au navigateur d’exécuter une fonction plus tard, une seule fois, quand le délai (en millisecondes) est écoulé (MDN Web Docs, s. d.-d). La fonction donnée est une fonction de rappel, comme celle de map en semaine 7. setTimeout ne met pas le programme en pause : les lignes suivantes s’exécutent tout de suite. Quand le délai est écoulé, la fonction est rangée dans une file d’attente : elle s’exécute dès que le code en cours est terminé.

setTimeout, en image

Le texte du schéma : 1. le code en cours s’exécute de haut en bas, sans attendre le minuteur : il affiche A, confie la fonction B au navigateur avec setTimeout(B, 2000), puis affiche C ; 2. le minuteur du navigateur garde B et compte 2 secondes ; 3. le délai écoulé, B est rangée dans la file d’attente, où elle attend la fin du code en cours. Ce qui s’affiche : A, puis C, et B deux secondes plus tard.

setTimeout, l’exemple minimal

Le premier programme de la notion, annoté :

semaine-09/exemple/app.js
1console.log('A');
2setTimeout(() => {
3  console.log('B');
4}, 2000);
5console.log('C');
1
Exécutée tout de suite : la console affiche A.
2
setTimeout reçoit une fonction fléchée : il ne l’exécute pas, il la confie au navigateur.
3
Cette ligne est dans la fonction : elle attend.
4
Le délai, en millisecondes : 2000, donc 2 secondes.
5
Exécutée tout de suite après la ligne 2, sans attendre : la console affiche C. Deux secondes plus tard, elle affiche B.

setTimeout — attention et vérification

AvertissementAttention

Le message s’affiche tout de suite ? Vous avez écrit setTimeout(showList(), 2000).

Les parenthèses exécutent la fonction immédiatement. Donnez la fonction sans l’appeler : setTimeout(showList, 2000), ou une fonction fléchée. C’est le même piège qu’avec addEventListener en semaine 8.

  • Vérifiez : log(1), setTimeout(() => log(2), 0), log(3).
  • Dans quel ordre s’affichent les trois nombres ?

Pas à pas ensemble — Chargement…, puis la liste (30 min)

  • Le formateur code, vous tapez en même temps, une étape à la fois.
  • Code et commentaires : // au-dessus de chaque ligne.
  • Dossier : pas-a-pas-minuteur ; vous tapez dans app.js.

Pas à pas, tous ensemble. Ouvrez le dossier pas-a-pas-minuteur : index.html contient un bouton « Charger les musées » (#action), un paragraphe de message (#message) et une liste vide (#liste) ; logic.js contient museumLabel, déjà écrite ; app.js commence par les lignes import, déjà écrites. Les commentaires. En JavaScript, un commentaire commence par //. Vous tapez chaque commentaire, sur sa propre ligne, juste au-dessus de la ligne qu’il explique.

Étape 1 — Le message d’attente. À la fin d’app.js, trouvez le bouton et le message, puis écoutez le clic.

Avant d’exécuter : après un clic, le message « Chargement… » disparaît-il tout seul ?

// Le bouton de la page
const button = document.querySelector('#action');
// Le paragraphe du message
const message = document.querySelector('#message');
// Au clic : le visiteur sait que sa demande est partie

Étape 2 — Deux secondes plus tard. Dans l’écouteur, sous la ligne message.textContent = 'Chargement...';, programmez la suite avec setTimeout.

Avant d’exécuter : combien de temps « Chargement… » reste-t-il affiché ?

semaine-09/pas-a-pas-minuteur/app.js
  // setTimeout : cette fonction s'exécutera dans 2 secondes
  setTimeout(() => {
    // 2 secondes plus tard : le résumé remplace l'attente
    message.textContent = `${MUSEUMS.length} musées`;
  }, 2000);

Enregistrez, puis cliquez.

Vous devez voir : « Chargement… », puis, deux secondes plus tard, « 34 musées ».

Perdu ? Copiez rattrapage/minuteur/etape-2/app.js à la place de votre app.js.

Étape 3 — La liste arrive avec le résumé. Deux ajouts. D’abord, sous la ligne const message = …, trouvez la liste :

// La liste de la page, vide pour l'instant
const list = document.querySelector('#liste');

Puis, dans la fonction donnée à setTimeout, sous la ligne du résumé, ajoutez la boucle de la semaine 8 :

    // for...of : un <li> par musée, comme en semaine 8

      // Un nouveau <li>
      const item = document.createElement('li');
      // Son texte vient de la logique : museumLabel
      item.textContent = museumLabel(museum);
      // Ajouté à la fin de la liste
      list.append(item);
    }

Avant d’exécuter : la liste apparaît-elle avant, avec ou après « 34 musées » ?

Enregistrez, puis cliquez.

Vous devez voir : « Chargement… » ; deux secondes plus tard, « 34 musées » et 34 lignes en même temps, la première « musée de Dinan - Dinan ».

Perdu ? Copiez rattrapage/minuteur/etape-3/app.js à la place de votre app.js.

Étape 4 — Une ligne écrite après, exécutée avant. Cliquez une deuxième fois, et attendez : la liste est en double (68 lignes). Il faut vider l’ancienne liste dès le clic. Dans l’écouteur, sous la ligne }, 2000);, ajoutez :

Avant d’exécuter : cette ligne est écrite après setTimeout. S’exécute-t-elle avant ou après l’affichage de la liste ?

semaine-09/pas-a-pas-minuteur/app.js
  // Ici, après setTimeout : exécutée AVANT son callback
  list.textContent = '';

Enregistrez. Cliquez, attendez la liste, puis cliquez une deuxième fois.

// logic.js
export function countdownSteps(from) {
  const steps = [];
  for (let n = from; n >= 1; n--) {
    steps.push(`${n}`);
  }
  steps.push('Ouvert !');
  return steps;
}

// app.js
const button = document.querySelector('#action');

AstuceÀ retenir
  • setTimeout(fonction, délai) : la fonction s’exécutera plus tard ; le délai est en millisecondes.
