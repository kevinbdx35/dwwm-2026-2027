Objectifs

  • Garder une donnée dans le navigateur avec localStorage : setItem, getItem, removeItem.
  • Transformer un tableau ou un objet en texte JSON avec JSON.stringify, et l’inverse avec JSON.parse.
  • Traiter le cas où rien n’est encore enregistré : getItem renvoie null.

Comment se passe la matinée. D’abord la veille, sur les données rangées dans le navigateur. Puis une seule notion : JSON et localStorage. Hier, response.json() transformait la réponse de l’API en objets JavaScript ; ce matin, vous voyez ce format de texte, JSON, et vous vous en servez pour garder des favoris après un rechargement de la page. La matinée se termine par les 10 minutes « Où j’en suis », annoncées lundi.

JSON et localStorage (15 min)

  • Pourquoi : garder des favoris après un rechargement de la page.
  • localStorage : une clé, un texte, gardés par le navigateur.
  • JSON : un tableau ou un objet, écrit en texte.
  • JSON.stringify pour enregistrer, JSON.parse pour relire.

Pourquoi. Un visiteur choisit trois musées favoris, recharge la page : tout a disparu. Une variable JavaScript ne vit que le temps de la page. Pour retrouver ces choix à la prochaine visite, il faut les ranger dans le navigateur.

Définition. localStorage est un espace de rangement du navigateur, propre à chaque site : setItem(clé, texte) range un texte sous une clé, getItem(clé) le relit (ou renvoie null s’il n’y a rien), removeItem(clé) l’efface ; le contenu reste après la fermeture du navigateur (MDN Web Docs, s. d.-d, s. d.-c). Il ne garde que du texte. JSON est un format de texte qui écrit des données comme des tableaux et des objets JavaScript : JSON.stringify transforme un tableau ou un objet en texte (MDN Web Docs, s. d.-b), JSON.parse fait l’inverse (MDN Web Docs, s. d.-a). C’est le format de la réponse de l’API d’hier : response.json() faisait ce travail de lecture pour vous.

JSON et localStorage, en image

Le texte du schéma : à gauche, dans la page, un tableau de deux identifiants. À droite, dans le navigateur, localStorage : sous la clé favoris, le texte '["M0194","M0213"]'. Pour enregistrer, de gauche à droite : JSON.stringify, puis setItem. Pour relire, de droite à gauche : getItem, puis JSON.parse. S’il n’y a rien sous la clé, getItem renvoie null.

JSON et localStorage, l’exemple minimal

Le premier programme de la notion, annoté : enregistrer, puis relire.

semaine-09/exemple/app.js
1const favorites = ['M0194', 'M0213'];

2const text = JSON.stringify(favorites);
3localStorage.setItem('favoris', text);

4const stored = localStorage.getItem('favoris');
5if (stored !== null) {
6  const again = JSON.parse(stored);
  console.log(again.length);
}
1
Un tableau JavaScript : il disparaît quand la page se recharge.
2
JSON.stringify l’écrit en texte : '["M0194","M0213"]'.
3
setItem range ce texte dans le navigateur, sous la clé 'favoris'.
4
getItem relit le texte rangé sous cette clé, même après un rechargement.
5
S’il n’y a rien sous cette clé, getItem renvoie null : on traite ce cas d’abord (style défensif).
6
JSON.parse retransforme le texte en tableau : again.length vaut 2.

JSON et localStorage — attention et vérification

AvertissementAttention

Sans JSON.stringify, setItem enregistre le texte M0194,M0213 : JSON.parse ne sait pas le relire.

localStorage.setItem('favoris', favorites) enregistre ce texte, qui n’est pas du JSON. À la relecture, JSON.parse s’arrête : SyntaxError: Unexpected token 'M', "M0194,M0213" is not valid JSON (fiche « Lire un message d’erreur »). Enregistrez toujours JSON.stringify(favorites).

  • Vérifiez : que renvoie getItem pour une clé jamais enregistrée ?
  • Et JSON.stringify({ id: 'M0194' }) : quel est son type ?

Étape 2 — Relire. Sous la ligne // Étape 2 — sous cette ligne…, à la fin du fichier, écrivez la fonction loadFavorites.

Avant d’exécuter : que renvoie getItem la toute première fois, quand rien n’est enregistré ?

semaine-09/pas-a-pas-favoris/app.js
// Relit les favoris rangés dans le navigateur
function loadFavorites() {
  // getItem : le texte rangé sous KEY, ou null si rien
  const text = localStorage.getItem(KEY);
  // Rien d'enregistré : on part d'un tableau vide
  if (text === null) {
    // Un tableau vide : aucun favori
    return [];
  }
  // JSON.parse : le texte redevient un tableau
  return JSON.parse(text);
}

Puis, en haut du fichier, remplacez la ligne let favorites = []; par celle-ci, avec son commentaire :

semaine-09/pas-a-pas-favoris/app.js
// Au chargement : les favoris déjà enregistrés
let favorites = loadFavorites();

Enregistrez, puis rechargez la page.

Vous devez voir : « 1 favori(s) : M0194 » dès le chargement : le favori de l’étape 1 est revenu. Cliquez de nouveau sur « Ajouter : musée de Dinan » : « 2 favori(s) : M0194, M0194 ». Le même musée y est deux fois : c’est l’étape 3.

Exercices — JSON et localStorage

Tous les exercices partent de la même page : un résumé, la liste des musées en boutons, et le bouton « Tout retirer ». Chaque exercice a quatre fichiers : logic.js (la consigne de la logique en commentaire), app.js (la consigne de l’affichage, et les lignes import déjà écrites), index.html et style.css. Toujours dans cet ordre : d’abord la logique et ses tests (node --test nom.test.js, depuis semaine-09), puis l’affichage, dans le navigateur. La logique ne touche jamais à localStorage : Node n’en a pas. Elle reçoit un texte ou un tableau, et renvoie un résultat ; c’est app.js qui lit et écrit dans le navigateur.
