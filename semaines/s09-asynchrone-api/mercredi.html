Sans soutien prévu, vous êtes en autonomie toute la journée : commencez directement le parcours d’autonomie, par ses lignes 1 à 3 (R4, guidé, puis R5 et R6, semi-guidés).

  • Objectif : vos exercices faits, sur les besoins que vous avez déclarés.
  • Pourquoi : retravailler ce qui vous bloque, avant fetch, demain.

Déroulé

  1. Rappel (5 min, à 9 h 05) : trois questions courtes.
  2. Récupérer (5 min) : git pull dans dwwm-soutien.

Le projet en binôme : qui fait quoi

  • Binôme : ______ (donné par le formateur).
  • Le pilote tape et dit ce qu’il écrit.
  • Le copilote lit la consigne, guide, relit chaque ligne.
  • Toutes les 20 minutes : échangez les rôles.
  • Le dépôt de l’un, puis le dépôt de l’autre.

Sur les créneaux du projet, vous travaillez à deux sur un seul ordinateur à la fois. Chacun garde son propre dépôt explorateur-musees : le jour de la défense, chacun explique tout son code.

  1. Le pilote tape. Il dit à voix haute ce qu’il écrit. Il ne tape rien que le copilote n’a pas compris.
  2. Le copilote ne touche pas au clavier. Il lit la consigne, dit quoi faire, relit chaque ligne tapée.
  3. Toutes les 20 minutes (minuteur), échangez les rôles.
  4. Travaillez d’abord sur le dépôt de l’un (45 min pour US-3), puis refaites le travail sur le dépôt de l’autre.
  5. Chaque Pull Request : son auteur la relit avec la grille de relecture ; son binôme la relit avec la même grille et écrit un commentaire dans la Pull Request ; son auteur la fusionne.

À trois (quand le groupe est en nombre impair) : la troisième personne tient le minuteur et la grille ; à chaque échange, les trois rôles tournent. Le travail se fait sur les trois dépôts, l’un après l’autre.

Relire la Pull Request de son binôme. Les dépôts sont publics : aucun droit à donner.

  1. Sur GitHub, ouvrez le dépôt explorateur-musees de votre binôme, onglet Pull requests, puis sa Pull Request.
  2. Onglet Files changed : lisez chaque ligne ajoutée, la grille à côté de vous.
  3. Onglet Conversation : écrivez un commentaire de deux phrases : une chose bien faite, puis une question ou une remarque tirée de la grille. Cliquez sur Comment.

Vous devez voir : votre commentaire sous la description de la Pull Request, avec votre nom de compte GitHub.

Ligne 1 : R4 — la carte réagit

Palier 1 : guidé. Durée : 20 min. Dossier r4-carte-reagit, fichier style.css.

Pourquoi. Dans le projet, chaque musée a un lien ou un bouton. Le visiteur doit voir qu’il peut cliquer : le lien change quand le pointeur passe dessus. Mais tout le monde n’utilise pas une souris : au clavier, on avance de lien en lien avec la touche Tab, et il faut voir où l’on est. En CSS, une pseudo-classe est un mot ajouté à un sélecteur, après deux-points, qui vise un élément dans un certain état : :hover quand le pointeur est dessus (MDN Web Docs, s. d.-g), :focus-visible quand il a le focus du clavier (MDN Web Docs, s. d.-b).

Les commentaires. Vous tapez le code et ses commentaires. En CSS, un commentaire s’écrit /* … */, sur sa propre ligne, juste au-dessus de la ligne qu’il explique.

Avant de commencer. Ouvrez r4-carte-reagit/index.html avec Live Preview, puis Ouvrir dans le navigateur. Ouvrez r4-carte-reagit/style.css dans VS Code : vous écrivez à la fin du fichier, sous la dernière ligne. Vous devez voir : trois cartes de musée, chacune avec un lien bleu « Voir la fiche ». Passez le pointeur sur un lien : rien ne change.

Étape 1 — :hover sur le lien. À la fin de style.css :

semaine-09/r4-carte-reagit/style.css
/* :hover : le pointeur de la souris est sur le lien */
.carte-lien:hover {
  /* Un bleu plus foncé : le lien réagit */
  background: #143f80;
}

Enregistrez, puis rechargez la page du navigateur. Passez le pointeur sur un lien, puis retirez-le.

Vous devez voir : le lien devient bleu foncé quand le pointeur est dessus, et redevient bleu quand le pointeur s’en va. La règle ne s’applique que pendant le survol.

Perdu ? Copiez rattrapage/r4-carte/etape-1/style.css à la place de votre style.css.

Étape 2 — :hover sur la carte. :hover marche sur n’importe quel élément, pas seulement sur les liens. Sous la règle de l’étape 1 :

Avant d’enregistrer : quand le pointeur est sur le lien, est-il aussi sur la carte ?

semaine-09/r4-carte-reagit/style.css
/* :hover sur la carte : le pointeur est sur la carte */
.carte:hover {
  /* La bordure de la carte devient bleue */
  border-color: #1f5fbf;
}

Enregistrez, puis rechargez. Passez le pointeur sur une carte, puis sur son lien.

Vous devez voir : la bordure de la carte survolée devient bleue ; les deux autres restent grises. Sur le lien, les deux règles s’appliquent en même temps : le lien est dans la carte, donc le pointeur est sur les deux.

Perdu ? Copiez rattrapage/r4-carte/etape-2/style.css.

Étape 3 — :focus-visible : le clavier. Lâchez la souris. Cliquez dans la barre d’adresse du navigateur, puis appuyez plusieurs fois sur la touche Tab.

Vous devez voir : le focus passe d’un lien « Voir la fiche » au suivant, avec un contour fin dessiné par le navigateur. Le lien ne fonce pas : :hover ne concerne que le pointeur. Rendez ce contour bien visible. Sous la règle de l’étape 2 :

semaine-09/r4-carte-reagit/style.css
/* :focus-visible : le lien a le focus du clavier (Tab) */
.carte-lien:focus-visible {
  /* outline : un contour épais autour du lien */
  outline: 3px solid #1c1e21;
  /* outline-offset : l'écart entre le lien et le contour */
  outline-offset: 3px;
}

Enregistrez, rechargez, puis avancez de nouveau avec Tab.

Vous devez voir : un contour noir épais autour du lien qui a le focus, à 3 px du lien. Cliquez maintenant sur un lien avec la souris : la page descend jusqu’à « La fiche », sans contour autour du lien. :focus-visible laisse le navigateur décider quand le contour est utile : toujours au clavier.

Perdu ? Copiez rattrapage/r4-carte/etape-3/style.css.

Étape 4 — Le même effet pour la souris et le clavier. Au clavier, le lien a son contour, mais il ne fonce pas. Un sélecteur peut viser deux états, séparés par une virgule. Dans la règle de l’étape 1, remplacez le commentaire du haut et le sélecteur par ceux-ci ; l’intérieur de la règle ne change pas.

semaine-09/r4-carte-reagit/style.css
/* Souris ou clavier (:focus-visible) : le même effet */
.carte-lien:hover,
.carte-lien:focus-visible {
  /* Un bleu plus foncé : le lien réagit */
  background: #143f80;
}

Enregistrez, rechargez, puis avancez avec Tab.

Vous devez voir : le lien qui a le focus est bleu foncé et entouré du contour noir. Avec la souris, rien n’a changé : le lien fonce au survol.

Perdu ? Copiez rattrapage/r4-carte/etape-4/style.css.

Réussi si : chaque lien fonce au survol et au focus du clavier ; le focus du clavier a un contour épais ; la bordure de la carte survolée devient bleue.

Variante à faire seuls. Au survol de la carte, changez aussi la couleur de son fond (background), avec un gris très clair, par exemple #f6f7f9. Réussi si : vous n’avez ajouté que deux lignes (un commentaire et une déclaration), dans une règle qui existe déjà.

À retenir.

  • :hover : le pointeur est sur l’élément. :focus-visible : l’élément a le focus du clavier.
  • Ce qui réagit à la souris doit aussi réagir au clavier : a:hover, a:focus-visible.
  • Sur un téléphone, il n’y a pas de survol : aucune information ne doit dépendre de :hover seul.

Enregistrer et envoyer : depuis semaine-09, git status, git add r4-carte-reagit, git commit -m "Ajoute les réactions de la carte de R4", git push.

NoteAides
  • Le cours : cette page, le schéma et les quatre étapes ; la fiche de révision.
  • L’IA : CS50.ai (palier IA 1) : demandez pourquoi votre règle ne s’applique pas, pas le code.
  • MDN : :hover ; :focus-visible.

Ligne 2 : R5 — la carte réagit en douceur

Palier 2 : semi-guidé. Durée indicative : 20 min. Dossier r5-transition, fichier style.css. À faire après R4 : la page de départ est le résultat de R4.

Pourquoi. Dans R4, la couleur change d’un coup. Une transition fait passer une propriété d’une valeur à l’autre en un certain temps : le changement se voit mieux (MDN Web Docs, s. d.-f). Certaines personnes règlent leur système pour avoir moins d’animations : une ligne suffit pour respecter ce choix (MDN Web Docs, s. d.-a).

Avant de commencer. Ouvrez r5-transition/index.html avec Live Preview, puis dans le navigateur. Vous devez voir : les trois cartes de R4 ; au survol, le lien fonce d’un coup.

Étape 1 — Un essai : la transition sur l’état survolé. À la fin de style.css :

Avant d’enregistrer : le changement sera-t-il doux à l’arrivée du pointeur, à son départ, ou les deux ?

semaine-09/r5-transition/style.css
/* Essai : la transition écrite sur l'état survolé */
.carte-lien:hover {
  /* La couleur de fond change en 0.3 seconde */
  transition: background-color 0.3s;
}

Enregistrez, rechargez. Passez lentement le pointeur sur un lien, puis retirez-le.

Vous devez voir : le lien fonce en douceur quand le pointeur arrive, mais il redevient bleu d’un coup quand le pointeur s’en va. C’est le piège : écrite dans :hover, la transition n’existe que pendant le survol.

Perdu ? Copiez rattrapage/r5-transition/etape-1/style.css à la place de votre style.css.

Étape 2 — La transition sur l’état de départ. Remplacez la règle de l’étape 1 par celle-ci : seuls le commentaire et le sélecteur changent.

semaine-09/r5-transition/style.css
/* transition : écrite sur l'état de départ du lien */
.carte-lien {
  /* La couleur de fond change en 0.3 seconde */
  transition: background-color 0.3s;
}

Enregistrez, rechargez, puis survolez un lien.

Vous devez voir : le lien fonce en douceur, et redevient bleu en douceur. La valeur se lit ainsi : la propriété à surveiller (background-color), puis la durée (0.3s, 0,3 seconde).

Perdu ? Copiez rattrapage/r5-transition/etape-2/style.css.

Étape 3 — La bordure de la carte. Sous la règle de l’étape 2, écrivez seuls une règle pour .carte, sur le même modèle : la propriété à surveiller est border-color, la durée 0.3s. N’oubliez pas les deux commentaires.

Vous devez voir : au survol d’une carte, sa bordure passe du gris au bleu en douceur, dans les deux sens.

Perdu ? Copiez rattrapage/r5-transition/etape-3/style.css.

Étape 4 — Respecter le réglage « moins d’animations ». À la fin de style.css. Vous connaissez @media avec une largeur d’écran (semaine 5) ; ici, la condition est un réglage du système du visiteur.

semaine-09/r5-transition/style.css
/* Le visiteur a demandé moins d'animations à son système */
@media (prefers-reduced-motion: reduce) {
  /* La carte et son lien : plus de transition */
  .carte,
  .carte-lien {
    /* none : le changement est immédiat */
    transition: none;
  }
}

Enregistrez, rechargez. Pour essayer sans toucher aux réglages de votre ordinateur, dans Chrome : ouvrez les outils (F12), puis le menu des commandes (), tapez rendering, ouvrez l’onglet Rendering, puis réglez Emulate CSS media feature prefers-reduced-motion sur reduce. Les noms des menus peuvent être traduits dans votre navigateur.

Vous devez voir : avec le réglage sur reduce, les couleurs changent d’un coup, comme dans R4 ; remis sur No emulation, elles changent en douceur.

Perdu ? Copiez rattrapage/r5-transition/etape-4/style.css.

Réussi si : le lien et la bordure changent en douceur dans les deux sens ; avec le réglage reduce, ils changent d’un coup.

Variante à faire seuls. Dans la règle de l’étape 2, changez la durée : 0.3s devient 1s, puis 0.1s. Survolez un lien à chaque fois, puis remettez 0.3s. Réussi si : vous savez dire laquelle des trois durées est la plus confortable, et pourquoi, en une phrase écrite en commentaire au-dessus de la règle.

À retenir.

  • transition s’écrit sur l’état de départ, pas dans :hover.
  • Sa valeur : la propriété à surveiller, puis la durée (background-color 0.3s).
  • @media (prefers-reduced-motion: reduce) : on y retire les transitions.

Enregistrer et envoyer : git status, git add r5-transition, git commit -m "Ajoute les transitions de R5", git push.

NoteAides
  • Le cours : cette page, les quatre étapes ; l’exercice R4, pour :hover.
  • L’IA : CS50.ai (palier IA 1) : demandez pourquoi votre transition ne marche que dans un sens, pas le code.
  • MDN : transition ; prefers-reduced-motion.

Ligne 3 : R6 — la photo du musée

Palier 2 : semi-guidé. Durée indicative : 20 min. Dossier r6-photo-musee, fichier style.css.

Pourquoi. Dans une liste de cartes, les photos n’ont jamais les mêmes proportions : l’une est en largeur, l’autre en hauteur. Pour que toutes les cartes se ressemblent, on donne aux photos le même cadre. object-fit dit comment l’image occupe ce cadre (MDN Web Docs, s. d.-d) ; overflow dit ce que devient ce qui dépasse d’un élément (MDN Web Docs, s. d.-e).

Avant de commencer. Ouvrez r6-photo-musee/index.html avec Live Preview, puis dans le navigateur. Les deux images sont des dessins faits pour le cours. Vous devez voir : deux cartes ; la première image est en largeur, la seconde en hauteur : la seconde carte est beaucoup plus haute que la première.

Étape 1 — Le même cadre pour toutes les photos. À la fin de style.css :

Avant d’enregistrer : que va devenir le phare, dans un cadre de 10rem de haut ?

semaine-09/r6-photo-musee/style.css
/* Le cadre de la photo : le même dans chaque carte */
.photo {
  /* width : toute la largeur de la carte */
  width: 100%;
  /* height : 10rem de haut, pour toutes les photos */
  height: 10rem;
}

Enregistrez, puis rechargez.

Vous devez voir : les deux cartes ont la même hauteur, mais les images sont déformées : le bâtiment est aplati, le phare est écrasé. Sans consigne, l’image remplit le cadre en perdant ses proportions : c’est la valeur par défaut, fill.

Perdu ? Copiez rattrapage/r6-photo/etape-1/style.css à la place de votre style.css.

Étape 2 — object-fit: cover. Ajoutez deux lignes à la fin de la règle .photo, avant l’accolade fermante.

semaine-09/r6-photo-musee/style.css
  /* object-fit cover : remplit le cadre, sans déformer */
  object-fit: cover;

Enregistrez, puis rechargez.

Vous devez voir : plus rien n’est déformé. Chaque image remplit son cadre ; ce qui ne rentre pas est coupé : on ne voit plus que le milieu du phare.

Perdu ? Copiez rattrapage/r6-photo/etape-2/style.css.

Étape 3 — Un essai : contain. Dans la règle .photo, remplacez le mot cover par contain, dans la déclaration et dans son commentaire (« toute l’image, sans déformer »).

Vous devez voir : chaque image est entière, sans déformation, mais elle ne remplit plus son cadre : le fond gris apparaît de chaque côté. Comparez avec le schéma. Pour une photo dans une carte, cover donne le meilleur résultat : remettez cover, et son commentaire.

Perdu ? rattrapage/r6-photo/etape-3/style.css contient l’essai avec contain.

Étape 4 — overflow: hidden : couper ce qui dépasse. Regardez de près les deux coins du haut d’une carte (agrandissez la page avec le zoom du navigateur, à 200 %). La carte a des coins arrondis, mais la photo est un rectangle : ses coins dépassent de l’arrondi. Sous la règle .photo :

semaine-09/r6-photo-musee/style.css
/* La carte : son contenu reste dans l'arrondi */
.carte {
  /* overflow hidden : ce qui dépasse est coupé */
  overflow: hidden;
}

Enregistrez, puis rechargez.

Vous devez voir : les coins du haut de chaque photo suivent l’arrondi de la carte.

Perdu ? Copiez rattrapage/r6-photo/etape-4/style.css.

Réussi si : à 375 et à 1280 px, les deux photos ont la même hauteur, aucune n’est déformée, et leurs coins du haut sont arrondis.

Variante à faire seuls. Dans la carte du phare, on ne voit que le milieu du dessin. Cherchez dans MDN la propriété object-position, et montrez le haut du phare. Réussi si : la lanterne jaune du phare est visible, et vous n’avez écrit qu’une règle, pour la deuxième image seulement.

À retenir.

  • Un cadre : width et height sur l’image ; sans rien d’autre, l’image se déforme.
  • object-fit: cover remplit le cadre et coupe ce qui dépasse ; contain montre tout et laisse du vide.
  • overflow: hidden sur un élément coupe ce qui dépasse de lui, par exemple de ses coins arrondis.

Enregistrer et envoyer : git status, git add r6-photo-musee, git commit -m "Ajoute le cadre des photos de R6", git push.

NoteAides
  • Le cours : R6, la photo du musée, le schéma et les quatre étapes.
  • L’IA : CS50.ai (palier IA 1) : demandez pourquoi votre image est déformée ou coupée, pas le code.
  • MDN : object-fit ; overflow.

Ligne 8 : R8 — une fenêtre par-dessus la page, puis les paliers 3

Palier 3 : autonome. Durée indicative : 30 min. Dossier r8-fenetre.

La page affiche un en-tête collant, huit cartes et, tout en bas, un voile et une fenêtre « Bienvenue », encore sans mise en place. À vous de les placer par-dessus la page :

  • le voile, noir à moitié transparent, couvre toute la fenêtre du navigateur, en-tête compris ;
  • la fenêtre « Bienvenue » reste à l’écran pendant le défilement, devant le voile.

Vous connaissez position et z-index (exercices R1 et R2 de la semaine 8). Il vous manque une valeur de position, et une explication : même avec z-index: 999, l’en-tête passera devant votre voile. Cherchez pourquoi dans la page MDN sur le contexte d’empilement (MDN Web Docs, s. d.-c), puis corrigez, dans index.html ou dans style.css.

Réussi si : à 375 et à 1280 px, la fenêtre « Bienvenue » est entièrement visible et ne bouge pas quand la page défile ; le voile couvre toute la page, l’en-tête aussi ; un commentaire d’une phrase, dans style.css, explique pourquoi z-index: 999 ne suffisait pas.
