Objectifs

  • Réagir à l’envoi d’un formulaire avec l’événement submit, sans recharger la page.
  • Lire et nettoyer la valeur d’un champ (value, trim).
  • Afficher un message d’erreur clair, à côté du champ, quand la saisie n’est pas valide.

Comment se passe la matinée. Une seule notion : la validation côté client. Vous connaissez les formulaires HTML (semaine 5, et l’exercice R3 d’hier) et les événements (lundi) ; ce matin, JavaScript vérifie ce qui a été tapé avant de s’en servir. Cet après-midi, le projet n° 1 commence par un formulaire de recherche.

Matin — Formulaires : valider côté client

Rappel (5 min)

  1. const { Ville: city } = museum; crée quelle variable ?
  2. Que vaut [2, 4].reduce((sum, n) => sum + n, 10) ?
  3. Quel attribut relie un label à son champ ?

Trois questions courtes, sans regarder vos notes : la veille (mardi), la semaine passée, puis plus loin. Répondez sur une feuille ; la correction suit, à l’oral.

Valider côté client (15 min)

  • Pourquoi : prévenir tout de suite d’une saisie incomplète.
  • submit + preventDefault() : on garde la main, la page reste.
  • Un message visible, à côté du champ, qui dit quoi faire.

Pourquoi. Un visiteur qui envoie un champ vide, ou une seule lettre, doit savoir tout de suite ce qui ne va pas, et comment le corriger, sans perdre ce qu’il a tapé. Vérifier dans le navigateur, avant d’utiliser la saisie, c’est la validation côté client. Elle sert le confort du visiteur ; elle ne protège rien : un serveur revérifie toujours ce qu’il reçoit (semaine 16), car tout ce qui vient du navigateur peut être modifié (OWASP Foundation, s. d.).

Définition. La validation côté client vérifie la saisie dans le navigateur, avant de l’utiliser (MDN Web Docs, s. d.-d). L’événement submit se produit quand le formulaire est envoyé (bouton ou Entrée) ; event.preventDefault() empêche le comportement par défaut, l’envoi et le rechargement de la page (MDN Web Docs, s. d.-b). field.value.trim() donne le texte du champ, sans les espaces autour (MDN Web Docs, s. d.-c). Le message d’erreur s’écrit avec textContent, dans un élément relié au champ par aria-describedby (déjà écrit dans le HTML des exercices) : un lecteur d’écran le lit avec le champ (MDN Web Docs, s. d.-a).

Valider côté client, en image

Le texte du schéma : le formulaire est envoyé (submit), par le bouton ou par Entrée ; preventDefault() garde la page ; value.trim() donne le texte du champ. Valide ? Non : un message d’erreur, visible sous le champ. Oui : le résultat, et le message effacé.

Valider côté client — attention et vérification

AvertissementAttention

Sans event.preventDefault(), le formulaire est envoyé et la page se recharge : votre message s’affiche une fraction de seconde, puis tout disparaît, console comprise. Écrivez event.preventDefault(); en première ligne de l’écouteur submit.

  • Vérifiez : pourquoi submit, et pas click ?
  • Que donne ' Brest '.trim() ?

Pas à pas. Ouvrez pas-a-pas-formulaire/index.html : un formulaire avec un champ « Ville », son label, un bouton, et deux paragraphes vides, #erreur et #resultat. Le <form> porte l’attribut novalidate : les bulles du navigateur sont coupées, nos messages les remplacent. app.js trouve déjà les quatre éléments. Avant de commencer. Vous devez voir : le formulaire, et dans la console, les quatre éléments, sans erreur.

Étape 1 — Garder la main. Un écouteur submit qui empêche le rechargement.

Avant d’exécuter : « envoyé ! » restera-t-il dans la console ?

semaine-08/pas-a-pas-formulaire/app.js
// submit : le formulaire est envoyé (bouton ou Entrée)
form.addEventListener('submit', (event) => {
  // preventDefault : la page ne se recharge pas
  event.preventDefault();
  // Pour voir que l'écouteur s'exécute
  console.log('envoyé !');
});

Enregistrez, rechargez, cliquez sur « Chercher », puis tapez Entrée dans le champ.

Vous devez voir : « envoyé ! » dans la console, avec un petit « 2 » à côté (la console regroupe deux messages identiques), et la page ne se recharge pas.

Perdu ? Copiez rattrapage/formulaire/etape-1/app.js à la place de votre app.js, puis repartez avec le groupe.

Étape 2 — Lire le champ. Un deuxième écouteur submit : le texte du champ, nettoyé, puis affiché.

Avant d’exécuter : que s’affiche-t-il si l’on tape « Vannes » ?

semaine-08/pas-a-pas-formulaire/app.js
// Un deuxième écouteur submit : lire le champ
form.addEventListener('submit', (event) => {
  // La page ne se recharge pas
  event.preventDefault();
  // value : le texte du champ ; trim : sans espaces autour
  const city = field.value.trim();
  // Le résultat, écrit dans la page
  result.textContent = `Recherche : ${city}`;
});

Enregistrez, rechargez, tapez « Vannes », envoyez.

Vous devez voir : « Recherche : Vannes », sans les espaces. Envoyez le champ vide : « Recherche : », sans rien : il faut vérifier.

Perdu ? Copiez rattrapage/formulaire/etape-2/app.js à la place de votre app.js.

Étape 3 — Vérifier. Supprimez l’écouteur de l’étape 2, et mettez celui-ci à sa place : il lit, puis vérifie.

Avant d’exécuter : avec un champ vide, que verra-t-on sous le champ ?

semaine-08/pas-a-pas-formulaire/app.js
// Remplace l'écouteur de l'étape 2 : lire, puis vérifier
form.addEventListener('submit', (event) => {
  // La page ne se recharge pas
  event.preventDefault();
  // Le texte du champ, sans espaces autour
  const city = field.value.trim();
  // Champ vide : un message d'erreur, et aucun résultat
  if (city === '') {
    // Le message, visible sous le champ
    error.textContent = "Écrivez le nom d'une ville.";
    // On efface un ancien résultat
    result.textContent = '';
  } else {
    // Champ rempli : plus de message d'erreur
    error.textContent = '';
    // Le résultat, écrit dans la page
    result.textContent = `Recherche : ${city}`;
  }
});

Le message est entre guillemets doubles, "…" : il contient une apostrophe, qui fermerait des guillemets simples. Tapez l’apostrophe du clavier.

Enregistrez, rechargez ; envoyez vide, puis « Vannes ».

Vous devez voir : vide, le message rouge « Écrivez le nom d’une ville. » ; puis « Vannes » : le message disparaît, « Recherche : Vannes » s’affiche.

Perdu ? Copiez rattrapage/formulaire/etape-3/app.js à la place de votre app.js.

Étape 4 — Effacer en retapant. Quand on recommence à taper, le message d’erreur disparaît.

Avant d’exécuter : quel événement, submit ou input ?

semaine-08/pas-a-pas-formulaire/app.js
// Vider le message pendant la saisie
field.addEventListener('input', () => {
  // On efface l'erreur dès qu'on retape
  error.textContent = '';
});

Enregistrez, rechargez ; envoyez vide, puis tapez une lettre.

Vous devez voir : le message rouge disparaît dès la première lettre.

Perdu ? Copiez rattrapage/formulaire/etape-4/app.js à la place de votre app.js.

AstuceIndice 1 — l’idée

Dans la logique : un tableau vide au départ ; chaque règle non respectée y ajoute son message avec push. Trois if qui se suivent, sans else : les trois règles sont vérifiées à chaque fois. À la fin, on renvoie le tableau.

AstuceIndice 2 — le squelette 
// Dans checkProposal(proposal) :
//   1. un tableau vide : messages
//   2. si le nom, sans espaces autour, a moins de 3 caractères : ajouter son message
//   3. le code postal, sans espaces autour, dans une variable ;
//      s'il n'a pas 5 caractères, ou si Number(...) donne NaN : ajouter son message
//   4. si la ville, sans espaces autour, est vide : ajouter son message
//   5. renvoyer messages
AstuceIndice 3 — la solution, moins une ligne 
export function checkProposal(proposal) {
  const messages = [];
  if (proposal.name.trim().length < 3) {
    messages.push('Le nom compte au moins 3 caractères.');
  }
  const postcode = proposal.postcode.trim();
  // Il manque une ligne : le if du code postal (5 caractères, et un nombre).
    messages.push('Le code postal compte 5 chiffres.');
  }
  if (proposal.city.trim() === '') {
    messages.push('Écrivez la ville.');
  }
  return messages;
}

Palier 3 : autonome. Durée indicative : 25 min ; ce qui n’est pas fini se termine mercredi 02/12, dans le parcours d’autonomie.

Vous partez d’un dossier vide : aucun fichier n’est fourni. En ligne de commande, dans semaine-08, créez le dossier v3-pendant-la-saisie et ses quatre fichiers : index.html, style.css, logic.js et app.js.

Écrivez la page entière : un formulaire de recherche (un champ « Nom ou ville » avec son label, un bouton « Chercher », un paragraphe pour le message d’erreur), sa mise en forme, et checkQuery, reprise de v1. La validation se fait pendant la saisie : le message s’affiche à chaque lettre tapée, et le bouton « Chercher » reste désactivé tant qu’il y a un message. Au chargement, le bouton est déjà désactivé, sans message.

Pour relier vos fichiers, regardez comment v1-champ-obligatoire charge style.css et app.js dans index.html, et logic.js dans app.js. À vous de trouver la propriété qui désactive un bouton.

Réussi si : le dossier contient vos quatre fichiers ; à l’ouverture avec Live Preview, le bouton est grisé et aucun message n’est affiché ; « B » affiche « Écrivez au moins 2 caractères. » ; « Br » efface le message et active le bouton ; au clavier aussi.

NoteAutonome

Vous allez bloquer : c’est voulu, c’est le métier. Méthode : 1. lisez le message d’erreur en entier ; 2. cherchez-le dans la fiche « Lire un message d’erreur » ; 3. lisez la documentation ; 4. après 15 minutes bloqué sur le même point, demandez.
