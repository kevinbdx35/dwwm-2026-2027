Objectifs

  • Expliquer ce qu’est une faille XSS : du code glissé dans une donnée, puis exécuté par la page.
  • Reconnaître le danger d’innerHTML avec une donnée qui vient de l’extérieur.
  • Afficher toute donnée extérieure avec textContent, ou avec createElement et textContent.

Comment se passe la matinée. D’abord la veille, sur l’injection et le XSS. Puis une seule notion : la faille XSS. Depuis lundi, vous écrivez le texte avec textContent ; ce matin, vous découvrez pourquoi, en attaquant une page vous-mêmes. C’est du style défensif : le référentiel l’attend de vous, et le jury vous le demandera.

  3. Que vérifie Lighthouse dans sa catégorie « Accessibilité » ?

La faille XSS (15 min)

  • Pourquoi : une donnée de l’extérieur peut contenir du code.
  • XSS : ce code est exécuté par la page, chez le visiteur.
  • textContent : le texte reste du texte, jamais du HTML.

Pourquoi. Vos pages affichent des données qui ne viennent pas de vous : ce que tape le visiteur, ce que renvoie une API (dès la semaine 9). Si l’une d’elles contient du HTML, et que la page l’insère comme du HTML, elle peut contenir du JavaScript, qui s’exécutera chez chaque visiteur. C’est l’une des failles les plus courantes du web (OWASP Foundation, s. d.-a).

Définition. Une faille XSS (cross-site scripting) permet d’injecter du code dans une page, qui s’exécute ensuite dans le navigateur d’un visiteur (MDN Web Docs, s. d.-a). innerHTML lit son texte comme du HTML : une balise glissée dans la donnée devient un vrai élément (MDN Web Docs, s. d.-b). textContent écrit le texte tel quel : aucune balise n’est créée, rien ne s’exécute (MDN Web Docs, s. d.-c). Règle : toute donnée extérieure s’affiche avec textContent, ou avec createElement puis textContent (OWASP Foundation, s. d.-b).

La faille XSS, en image

Le texte du schéma : le visiteur tape une balise img dont l’attribut onerror appelle alert. Avec innerHTML, à gauche, le texte est lu comme du HTML : l’image est créée, son onerror s’exécute. Avec textContent, à droite, le texte reste du texte : la page affiche la balise, telle quelle.

La faille XSS, l’exemple minimal

Le premier programme de la notion, annoté : avant, puis après.

semaine-08/exemple/app.js
1const query = field.value;

2message.innerHTML = `Résultats pour : ${query}`;

3message.textContent = `Résultats pour : ${query}`;

4const item = document.createElement('li');
item.textContent = query;
list.append(item);
1
Une donnée qui vient de l’extérieur : le visiteur peut y taper n’importe quoi, des balises comprises.
2
Dangereux : innerHTML lit la donnée comme du HTML ; une balise devient un élément, son code peut s’exécuter.
3
Sûr : textContent écrit la donnée comme du texte.
4
Pour construire des éléments : createElement, puis textContent, jamais un morceau de HTML écrit dans une chaîne.

La faille XSS — attention et vérification

AvertissementAttention

innerHTML avec une donnée qui vient de l’extérieur (une saisie, une API, un fichier) : c’est une faille XSS. Le test : tapez <img src="x" onerror="alert('XSS')"> ; si une alerte s’ouvre, la page est attaquable. Remplacez par textContent.

  • Vérifiez : item.textContent = '<b>Brest</b>' affiche quoi ?
  • Et item.innerHTML = '<b>Brest</b>' ?

Étape 3 — Les résultats, sans danger. Les noms trouvés, en éléments créés un par un.

Avant d’exécuter : en cherchant « musée », combien de résultats ?

semaine-08/pas-a-pas-xss/app.js
// Les résultats : des éléments créés un par un
form.addEventListener('submit', (event) => {
  // La page ne se recharge pas
  event.preventDefault();
  // On vide la liste avant de la remplir
  list.textContent = '';
  // Les noms qui contiennent le texte tapé
  const found = names.filter((name) => name.includes(field.value));
  // Un <li> par nom, rempli avec textContent
  for (const name of found) {
    // createElement + textContent : aucun HTML interprété
    const item = document.createElement('li');
    // Le nom, comme du texte
    item.textContent = name;
    // Ajouté à la liste
    list.append(item);
  }
});

Enregistrez, rechargez ; cherchez « musée », puis l’attaque.

Vous devez voir : « musée » donne 4 résultats ; l’attaque n’en donne aucun, et aucune alerte.

Perdu ? Copiez rattrapage/xss/etape-3/app.js à la place de votre app.js.

AstuceIndice 1 — l’idée

Aucune balise écrite dans une chaîne : chaque élément est créé avec createElement, et chaque texte venu du visiteur passe par textContent ou par append. Le <li> contient deux morceaux : le <strong> du prénom, puis le texte de l’avis.

AstuceIndice 2 — le squelette 
// Dans showReview(review) :
//   1. créer un <li>
//   2. créer un <strong> ; y écrire le prénom (review.author), comme du texte
//   3. ajouter au <li> le <strong>, puis le texte « : avis »
//   4. ajouter le <li> à la liste
// Puis : pour chaque avis du tableau reviews, appeler showReview
// Puis : écouter le submit du formulaire ; empêcher le rechargement ;
//        construire un avis { author, text } avec les valeurs des deux champs ; appeler showReview
AstuceIndice 3 — la solution, moins une ligne 
function showReview(review) {
  const item = document.createElement('li');
  const strong = document.createElement('strong');
  // Il manque une ligne : sans elle, le prénom ne s'affiche pas.
  item.append(strong, ` : ${review.text}`);
  list.append(item);
}

  • MDN : Element.append() ; Document.createElement().
