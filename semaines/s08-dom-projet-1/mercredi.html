Matin — Soutien · autonomie pour les autres

Soutien

Si le formateur vous a indiqué des exercices, passez la matinée avec lui : la page Soutien de la semaine explique comment les récupérer.

Sans soutien prévu, vous êtes en autonomie toute la journée : commencez directement le parcours d’autonomie, par ses lignes 1 à 3 (les exercices guidés R1, R2 et R3).

Le soutien de ce matin

  • Dépôt : dwwm-soutien, git pull d’abord.
  • Objectif : vos exercices faits, sur les besoins que vous avez déclarés.
  • Pourquoi : retravailler ce qui vous bloque, avant le projet.

Déroulé

  1. Rappel (5 min, à 9 h 05) : trois questions courtes.
  2. Récupérer (5 min) : git pull dans dwwm-soutien.
  3. Pratique accompagnée : vos exercices, par groupes de 3 à 5.
  4. Point d’étape (après la pause) : une difficulté commune.
  5. La suite : le parcours d’autonomie, là où vous en êtes.

Rappel. 1. Que renvoie querySelector quand il ne trouve rien ? 2. Que fait addEventListener('click', show()), avec les parenthèses ? 3. Que renvoie [3, 8, 5].reduce((sum, n) => sum + n, 0) ?

Récupérer les exercices (le détail est sur la page Soutien de la semaine) : cd ~/dwwm/dwwm-soutien, puis git pull ; ouvrez E…/s08.md, dans le dossier de votre numéro ; copiez chaque exercice dans ~/dwwm/dwwm-tp/semaine-08/soutien/.

Vous devez voir : la liste de vos exercices de la semaine, et leur copie dans semaine-08/soutien/.

Ligne 1 : R1 — le badge « Favori » sur la carte d’un musée

Palier 1 : guidé. Durée : 30 min. Dossier r1-badge-favori, fichier style.css.

Pourquoi. Dans le projet de demain, une carte de musée porte un badge « Favori », dans son coin en haut à droite. Flexbox et Grid rangent les éléments les uns à côté des autres ; pour poser un élément par-dessus un autre, à un endroit précis, il faut la propriété position (MDN Web Docs, s. d.-d).

Les commentaires. Vous tapez le code et ses commentaires. En CSS, un commentaire s’écrit /* … */, sur sa propre ligne, juste au-dessus de la ligne qu’il explique.

Avant de commencer. Ouvrez r1-badge-favori/index.html avec Live Preview, puis Ouvrir dans le navigateur. Ouvrez r1-badge-favori/style.css dans VS Code : vous écrivez à la fin du fichier, sous la dernière ligne. Vous devez voir : deux cartes de musée ; dans chacune, le badge bleu « Favori » est sous la ville, à gauche.

Étape 1 — static, la valeur par défaut. Tout élément est en position: static : il est à sa place normale, dans l’ordre du HTML.

semaine-08/r1-badge-favori/style.css
/* position static : la valeur par défaut, dans le flux */
.badge {
  position: static;
  /* top n'a aucun effet sur un élément static */
  top: 1rem;
}

Enregistrez, puis rechargez la page du navigateur.

Vous devez voir : rien ne change. top est ignoré tant que l’élément est en static.

Perdu ? Copiez rattrapage/r1-badge/etape-1/style.css à la place de votre style.css.

Étape 2 — relative : décalé depuis sa place. Dans la règle .badge, remplacez static par relative, et les deux commentaires.

semaine-08/r1-badge-favori/style.css
/* position relative : décalé depuis sa place normale */
.badge {
  position: relative;
  /* top : 1rem plus bas que sa place normale */
  top: 1rem;
}

Enregistrez, puis rechargez.

Vous devez voir : chaque badge est descendu de 1rem (16 px), vers le bord bas de sa carte. La carte n’a pas grandi : la place d’origine du badge reste réservée.

Perdu ? Copiez rattrapage/r1-badge/etape-2/style.css.

Étape 3 — absolute : sorti du flux. Remplacez toute la règle .badge par celle-ci.

Avant d’enregistrer : où vont se placer les deux badges ?

semaine-08/r1-badge-favori/style.css
/* position absolute : sorti du flux, placé à la main */
.badge {
  position: absolute;
  /* top : à 0.5rem du haut de son repère */
  top: 0.5rem;
  /* right : à 0.5rem de la droite de son repère */
  right: 0.5rem;
}

Enregistrez, puis rechargez.

Vous devez voir : les deux badges ont quitté leur carte. Ils sont l’un sur l’autre, dans le coin en haut à droite de la page : on n’en voit plus qu’un. Les cartes sont moins hautes : un élément en absolute ne prend plus de place. C’est le schéma de gauche : sans repère, le badge se place par rapport à la page.

Perdu ? Copiez rattrapage/r1-badge/etape-3/style.css.

Étape 4 — relative sur le parent : le repère. Sous la règle .badge, ajoutez une règle pour la carte.

semaine-08/r1-badge-favori/style.css
/* position relative : la carte est le repère du badge */
.carte {
  position: relative;
}

Enregistrez, puis rechargez.

Vous devez voir : chaque badge est dans le coin en haut à droite de sa carte. La carte, elle, n’a pas bougé : relative sans top ni left ne déplace rien, il sert seulement de repère. C’est le schéma de droite, et c’est le couple à retenir : relative sur le parent, absolute sur l’enfant.

Perdu ? Copiez rattrapage/r1-badge/etape-4/style.css.

Étape 5 — z-index : qui passe devant. Réduisez la fenêtre : F12, mode responsive, 375 px de large. Dans la deuxième carte, le badge recouvre la fin du nom du musée. z-index dit quel élément passe devant quand deux éléments se recouvrent : le plus grand nombre gagne (MDN Web Docs, s. d.-e). Sous la règle .carte, tapez d’abord ceci.

semaine-08/r1-badge-favori/style.css
/* Le nom du musée, que le badge recouvre */
.carte h2 {
  /* z-index : le nom passe devant le badge */
  z-index: 1;
}

Enregistrez, puis rechargez.

Vous devez voir : rien ne change, le badge recouvre toujours le nom. C’est le piège : z-index n’a aucun effet sur un élément sans position. Ajoutez les deux lignes qui manquent, au début de la règle.

semaine-08/r1-badge-favori/style.css
/* Le nom du musée, que le badge recouvre */
.carte h2 {
  /* position relative : sans elle, z-index n'a aucun effet */
  position: relative;
  /* z-index : le nom passe devant le badge */
  z-index: 1;
}

Enregistrez, puis rechargez.

Vous devez voir : à 375 px, le nom du musée passe maintenant devant le badge.

Perdu ? Copiez rattrapage/r1-badge/etape-5/style.css.

Étape 6 — Laisser la place du badge. z-index choisit qui est devant ; il ne donne de place à personne. Ajoutez deux lignes à la fin de la règle .carte h2, avant l’accolade fermante.

semaine-08/r1-badge-favori/style.css
  /* padding-right : la place du badge, à droite du nom */
  padding-right: 5rem;

Enregistrez, puis rechargez.

Vous devez voir : à 375 px, le nom passe à la ligne avant le badge ; plus rien ne se recouvre.

Perdu ? Copiez rattrapage/r1-badge/etape-6/style.css.

Réussi si : à 375 et à 1280 px, chaque badge est dans le coin en haut à droite de sa carte, et aucun texte n’est recouvert.

Variante à faire seuls. Placez le badge dans le coin en bas à droite de la carte. Réussi si : vous n’avez changé qu’un mot dans la règle .badge.

À retenir.

  • relative sur le parent, absolute sur l’enfant : l’enfant se place dans le parent, avec top, right, bottom, left.
  • Un élément en absolute sort du flux : il ne prend plus de place.
  • z-index n’a d’effet que sur un élément qui a une position (ou qui est l’enfant direct d’un conteneur Flexbox ou Grid).

Enregistrer et envoyer : depuis semaine-08, git status, git add r1-badge-favori, git commit -m "Ajoute le badge de R1", git push.

NoteAides
  • Le cours : cette page, le schéma et les six étapes ; la fiche de révision.
  • L’IA : CS50.ai (palier IA 1) : demandez pourquoi votre badge n’est pas où vous l’attendez, pas le code.
  • MDN : position ; z-index.

Ligne 2 : R2 — l’en-tête qui reste en haut

Palier 1 : guidé. Durée : 20 min. Dossier r2-en-tete-collant, fichier style.css. À faire après R1.

Pourquoi. La liste des musées est longue. Quand on la fait défiler, le titre du site disparaît. position: sticky (« collant ») garde un élément visible : il défile avec la page, puis il se colle au bord de la fenêtre (MDN Web Docs, s. d.-d).

Avant de commencer. Ouvrez r2-en-tete-collant/index.html avec Live Preview, puis dans le navigateur ; mettez la fenêtre à 375 px de large (F12, mode responsive). Les cartes et leurs badges sont déjà écrits : c’est le résultat de R1. Vous devez voir : un bandeau noir « Musées de Bretagne », puis dix cartes. Faites défiler : le bandeau disparaît en haut.

Étape 1 — sticky, sans rien d’autre. À la fin de style.css :

Avant d’enregistrer : le bandeau va-t-il rester en haut ?

semaine-08/r2-en-tete-collant/style.css
/* position sticky : dans le flux, puis collé en haut */
.en-tete {
  position: sticky;
}

Enregistrez, rechargez, faites défiler.

Vous devez voir : rien ne change, le bandeau disparaît toujours. C’est le piège de sticky : sans top, il ne sait pas où se coller.

Perdu ? Copiez rattrapage/r2-en-tete/etape-1/style.css à la place de votre style.css.

Étape 2 — top : où se coller. Ajoutez deux lignes dans la règle .en-tete, avant l’accolade fermante.

semaine-08/r2-en-tete-collant/style.css
  /* top : se colle à 0 du haut de la fenêtre */
  top: 0;

Enregistrez, rechargez, faites défiler lentement.

Vous devez voir : le bandeau reste en haut de la fenêtre, et les cartes glissent dessous. Mais regardez les badges « Favori » : ils passent devant le bandeau.

Perdu ? Copiez rattrapage/r2-en-tete/etape-2/style.css.

Étape 3 — z-index : l’en-tête devant. Le bandeau et les badges ont tous une position ; sans z-index, celui qui est écrit le plus bas dans le HTML passe devant : les badges. Ajoutez deux lignes dans la règle .en-tete.

semaine-08/r2-en-tete-collant/style.css
  /* z-index : l'en-tête passe devant les badges */
  z-index: 1;

Enregistrez, rechargez, faites défiler.

Vous devez voir : les badges passent sous le bandeau, comme le reste des cartes. Ici, z-index agit sans rien ajouter : sticky est une position.

Perdu ? Copiez rattrapage/r2-en-tete/etape-3/style.css.

Réussi si : à 375 et à 1280 px, le bandeau reste en haut pendant tout le défilement, et rien ne passe devant lui.

Variante à faire seuls. Remplacez top: 0 par top: 1rem. Réussi si : vous savez dire où le bandeau se colle maintenant, et pourquoi. Remettez 0.

À retenir.

  • position: sticky a besoin de top : sans lui, rien ne colle.
  • L’élément reste dans le flux : il garde sa place, contrairement à absolute.
  • Devant ou derrière : z-index, sur un élément qui a une position.

Enregistrer et envoyer : git status, git add r2-en-tete-collant, git commit -m "Ajoute l'en-tête collant de R2", git push.

NoteAides
  • Le cours : cette page, les trois étapes ; l’exercice R1, pour z-index.
  • L’IA : CS50.ai (palier IA 1) : demandez pourquoi votre en-tête ne colle pas, pas le code.
  • MDN : position, partie sur sticky.

Ligne 3 : R3 — le formulaire de recherche de musées

Palier 1 : guidé. Durée : 25 min. Dossier r3-formulaire-recherche, fichier index.html.

Pourquoi. Demain matin, JavaScript vérifiera ce que le visiteur a tapé dans un formulaire. Avant, il faut connaître les champs que le HTML propose, et ce que le navigateur vérifie déjà seul. Vous connaissez form, label, input type="text" et button type="submit" (semaine 5) ; voici les autres (MDN Web Docs, s. d.-a).

Les commentaires. En HTML, un commentaire s’écrit <!-- … -->, sur sa propre ligne, juste au-dessus de la ligne qu’il explique. Vous les tapez aussi.

Avant de commencer. Ouvrez r3-formulaire-recherche/index.html avec Live Preview, puis dans le navigateur. Vous devez voir : un champ « Ville » et un bouton « Chercher ». Cliquez sur « Chercher », le champ vide : la page se recharge, et son adresse se termine par ?ville=.

Étape 1 — Un champ de recherche, obligatoire. Remplacez la ligne de l’input par ces deux lignes.

semaine-08/r3-formulaire-recherche/index.html
<!-- Champ de recherche (search), obligatoire (required) -->
<input id="ville" name="ville" type="search" required>

Enregistrez, rechargez, puis cliquez sur « Chercher », le champ vide.

Vous devez voir : le navigateur affiche un message près du champ, et la page ne se recharge pas : required refuse l’envoi d’un champ vide. Tapez Quimper, puis « Chercher » : l’adresse se termine par ?ville=Quimper. Le mot avant le = est l’attribut name du champ.

Perdu ? Copiez rattrapage/r3-formulaire/etape-1/index.html à la place de votre index.html.

Étape 2 — Une liste déroulante. Sous l’input, avant le paragraphe du bouton (MDN Web Docs, s. d.-b) :

semaine-08/r3-formulaire-recherche/index.html
<!-- label : relié à la liste par for et id -->
<label for="departement">Département</label>
<!-- select : une liste déroulante, un seul choix -->
<select id="departement" name="departement">
  <!-- option : un choix ; value est la valeur envoyée -->
  <option value="">Tous</option>
  <!-- Les Côtes-d'Armor, valeur 22 -->
  <option value="22">Côtes-d'Armor</option>
  <!-- Le Finistère, valeur 29 -->
  <option value="29">Finistère</option>
  <!-- L'Ille-et-Vilaine, valeur 35 -->
  <option value="35">Ille-et-Vilaine</option>
  <!-- Le Morbihan, valeur 56 -->
  <option value="56">Morbihan</option>
</select>

Enregistrez, rechargez. Tapez Quimper, choisissez « Finistère », puis « Chercher ».

Vous devez voir : l’adresse se termine par ?ville=Quimper&departement=29. Le formulaire envoie la value de l’option (29), pas son texte (« Finistère »).

Perdu ? Copiez rattrapage/r3-formulaire/etape-2/index.html.

Étape 3 — Un nombre. Sous le select :

<!-- label du nombre de résultats -->
<label for="nombre">Nombre de résultats (1 à 34)</label>

Étape 4 — Une adresse e-mail et un texte long. Sous le champ du nombre :

semaine-08/r3-formulaire-recherche/index.html
<!-- label de l'adresse e-mail -->
<label for="email">Votre e-mail, pour recevoir la liste</label>
<!-- type email : la forme de l'adresse est vérifiée -->
<input id="email" name="email" type="email">

<!-- label de la remarque -->
<label for="remarque">Une remarque</label>
<!-- textarea : un texte sur plusieurs lignes -->
<textarea id="remarque" name="remarque" rows="3"></textarea>

Enregistrez, rechargez. Tapez abc dans le champ e-mail, puis « Chercher » (avec une ville).

Vous devez voir : un message du navigateur, et pas d’envoi : il manque un @. Videz le champ : le formulaire part, car ce champ n’a pas required. Pour vos essais, tapez une adresse inventée, comme test@example.com : jamais votre vraie adresse.

Perdu ? Copiez rattrapage/r3-formulaire/etape-4/index.html.

Étape 5 — Trois boutons. Remplacez le paragraphe du bouton « Chercher » par celui-ci.

semaine-08/r3-formulaire-recherche/index.html
<p>
  <!-- type submit : envoie le formulaire -->
  <button type="submit">Chercher</button>
  <!-- type button : n'envoie rien ; attend JavaScript -->
  <button type="button">Effacer</button>
  <!-- disabled : bouton grisé, impossible à cliquer -->
  <button type="button" disabled>Exporter (bientôt)</button>
</p>

Enregistrez, rechargez. Cliquez sur chacun des trois boutons, puis parcourez le formulaire avec la touche Tab.

Vous devez voir : « Chercher » envoie le formulaire ; « Effacer » ne fait rien : un type="button" n’envoie pas le formulaire, il attend qu’un écouteur JavaScript lui donne un rôle, comme les boutons de lundi après-midi ; « Exporter (bientôt) » est gris, et Tab ne s’y arrête pas.

Perdu ? Copiez rattrapage/r3-formulaire/etape-5/index.html.

Réussi si : le formulaire refuse l’envoi sans ville, avec 50 résultats ou avec l’e-mail abc ; il part avec Quimper seul.

Variante à faire seuls. Ajoutez un champ type="date", avec son label « Date de la visite ». Réussi si : le navigateur propose un calendrier.

À retenir.

  • type choisit le champ (search, number, email, date) : le navigateur adapte le clavier et vérifie la forme.
  • required refuse l’envoi d’un champ vide ; name nomme la valeur envoyée.
  • button type="submit" envoie le formulaire ; type="button" n’envoie rien ; disabled désactive.

Le navigateur vérifie donc déjà beaucoup, mais avec ses propres messages. Demain matin, JavaScript fera ses vérifications, avec vos messages.
