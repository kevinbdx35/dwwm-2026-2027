Semaine 8 — Fiche de révision

Formateur

Kevin Bardoux

Une page pour réviser la semaine. Lisez-la une fois, puis cachez-la et redites chaque point avec vos mots. Le détail de chaque notion est dans la page de la demi-journée.

Le DOM (lundi matin)

  • DOM : la page vue par JavaScript, un arbre d’éléments.
  • Trouver : document.querySelector('#id') ; s’il ne trouve rien : null.
  • Changer : element.textContent = '…' ; créer : createElement('li'), puis ajouter : append ; rien n’apparaît avant append.
  • Masquer : element.hidden = true ; l’élément reste dans la page, il n’est plus affiché.
  • Poser une classe CSS : element.classList.add('important'), sans point ; le style reste dans style.css.

Les événements (lundi après-midi)

  • element.addEventListener('click', fonction) : la fonction s’exécute à chaque clic.
  • Sans parenthèses : show, pas show().
  • input : à chaque lettre ; field.value : le texte du champ.

Logique et affichage (mardi matin)

  • logic.js calcule et renvoie, sans document : node --test le vérifie.
  • app.js trouve les éléments et écrit le résultat : vérifié dans le navigateur.
  • Live Preview, jamais le double-clic : les lignes import (déjà écrites) en ont besoin.

La décomposition (mardi après-midi)

  • const { Ville } = museum; : une variable Ville, qui vaut museum.Ville ; la casse compte.
  • Renommer : const { Nom_officiel: name } = museum;.
  • Dans les paramètres : function label({ Ville }) reçoit un musée entier.

Position et formulaires (mercredi)

  • Position : relative sur le parent, absolute sur l’enfant, placé avec top, right, bottom, left ; sticky a besoin de top.
  • z-index : qui passe devant ; aucun effet sur un élément sans position (sauf l’enfant direct d’un conteneur Flexbox ou Grid).
  • Champs : type (search, number, email, date), select et ses option, textarea ; required refuse l’envoi d’un champ vide.
  • Boutons : type="submit" envoie le formulaire, type="button" n’envoie rien, disabled désactive.

Valider côté client (jeudi matin)

  • submit sur le formulaire, et event.preventDefault() en première ligne.
  • field.value.trim(), puis un message visible, qui dit quoi faire.
  • Le serveur revérifie toujours : la validation côté client aide le visiteur, elle ne protège rien.

Le projet n° 1 et le GitHub Flow (jeudi après-midi)

  • Un dépôt public par projet ; premier commit : .gitignore, .env.example, README.md.
  • Une branche par histoire, une Pull Request relue avec la grille, la fusion, puis git switch main et git pull.
  • Les tests d’une histoire : node --test --test-name-pattern=museumLabel projet-1.test.js.

La faille XSS (vendredi matin)

  • XSS : du code glissé dans une donnée, puis exécuté par la page.
  • innerHTML lit du HTML ; textContent écrit du texte.
  • Toute donnée extérieure (saisie, API) : textContent, ou createElement puis textContent.

Déjà vu en live coding (semaines 5 et 6)

  • display : block prend toute la largeur ; inline reste dans la ligne, sans largeur ni hauteur ; inline-block reste dans la ligne et accepte une taille ; none retire l’élément de la page.
  • vw et vh : 1 % de la largeur, de la hauteur de la fenêtre ; min-height: 100vh : au moins la hauteur de l’écran.
  • Image fluide : img { max-width: 100%; } ; l’image n’est jamais plus large que son parent.

Vérifier avant de rendre (toute la semaine)

  • Les tests : node --test nom.test.js, depuis semaine-08, affiche ℹ fail 0 (palier 3 : nom.defi.test.js).
  • Le navigateur : la page affiche ce qui est demandé, et la console (F12) n’affiche aucune erreur en rouge.
  • VS Code : aucun souligné rouge.
