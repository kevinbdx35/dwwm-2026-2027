Objectifs

  • Sortir plusieurs valeurs d’un objet en une ligne, avec la décomposition.
  • Renommer une variable au passage (Nom_officiel devient name).
  • Décomposer directement dans les paramètres d’une fonction.

Comment se passe l’après-midi. Une seule notion : la décomposition d’un objet. C’est la sœur du spread de vendredi dernier : le spread range des valeurs dans un nouvel objet, la décomposition les sort d’un objet. Cet après-midi, on revient dans le terminal, avec Node : pas de page, seulement des objets. Jeudi, vous l’utiliserez dans le projet.

Après-midi — La décomposition

La décomposition (15 min)

  • Pourquoi : lire plusieurs clés d’un objet sans répéter son nom.
  • const { Ville } = museum; : Ville vaut museum.Ville.
  • Renommer : { Nom_officiel: name }.

Pourquoi. Les musées du fichier ont des clés longues, en français, avec des majuscules : Nom_officiel, Departement. Écrire museum.Nom_officiel, museum.Ville, museum.Departement à chaque ligne alourdit le code. La décomposition sort les valeurs utiles d’un coup, au début d’une fonction.

Définition. L’affectation par décomposition (destructuring) extrait des valeurs d’un objet dans des variables : const { Ville, Departement } = museum; crée les variables Ville et Departement, qui valent museum.Ville et museum.Departement (MDN Web Docs, s. d.). Pour donner un autre nom à la variable : const { Nom_officiel: name } = museum;. L’objet, lui, ne change pas.

La décomposition, en image

Le texte du schéma : l’objet museum a trois clés. const { Ville, Departement } = museum; crée deux variables, Ville ('Concarneau') et Departement ('Finistère'), en une ligne. Pour renommer, const { Nom_officiel: name } = museum; : la variable name reçoit la valeur de la clé Nom_officiel. L’objet ne perd rien : on le lit, on ne le vide pas.

La décomposition, l’exemple minimal

Le premier programme de la notion, annoté :

semaine-08/exemple/decomposer.js
const museum = { Nom_officiel: 'port musée', Ville: 'Douarnenez' };

1const { Ville } = museum;
2const { Nom_officiel: name } = museum;

3function label({ Nom_officiel, Ville: city }) {
  return `${Nom_officiel} - ${city}`;
}

4console.log(Ville, name, label(museum));
1
Les accolades à gauche du = : on sort la clé Ville dans une variable du même nom.
2
Le nom de la clé, deux-points, le nom de la variable : la variable s’appelle name.
3
Dans les paramètres : la fonction reçoit un musée entier, et le décompose aussitôt.
4
Douarnenez port musée port musée — Douarnenez.

La décomposition — attention et vérification

AvertissementAttention

La casse compte, et aucune erreur ne prévient : const { ville } = museum; donne undefined, car la clé s’appelle Ville. Avant d’écrire, relisez les clés exactes dans le fichier de données, ou affichez l’objet avec console.log.

  • Vérifiez : { Departement: dept } crée quelle variable ?
  • museum a-t-il changé ensuite ?

Pas à pas ensemble — Déballer un musée (30 min)

  • Le formateur code, vous tapez en même temps, une étape à la fois.
  • Code et commentaires : // au-dessus de chaque ligne.
  • Dossier : pas-a-pas-decomposition, fichier decomposer.js.
  • Perdu ? Dossier rattrapage/decomposition/, une étape à la fois.

Pas à pas. Ouvrez pas-a-pas-decomposition/decomposer.js : deux musées du Finistère, avec les clés du fichier Muséofile (Ministère de la Culture, s. d.). Dans le terminal : cd ~/dwwm/dwwm-tp/semaine-08/pas-a-pas-decomposition.

Avant de commencer. Lancez node decomposer.js. Vous devez voir : musée de la pêche / musée bigouden. Chaque étape ajoute ses lignes à la fin du fichier, et sa sortie à la fin de la console.

Étape 1 — Deux variables en une ligne. Sortez la ville et le département du premier musée.

Avant d’exécuter : quels noms auront les deux variables ?

semaine-08/pas-a-pas-decomposition/decomposer.js
// Décomposition : deux variables en une ligne
const { Ville, Departement } = museum;
// Ville et Departement existent maintenant
console.log(Ville, Departement);

Enregistrez, puis lancez node decomposer.js, depuis pas-a-pas-decomposition.

Vous devez voir, à la fin : Concarneau Finistère.

Perdu ? Copiez rattrapage/decomposition/etape-1/decomposer.js à la place de votre fichier, puis repartez avec le groupe.

Étape 2 — Renommer. Sortez le nom officiel dans une variable name.

Avant d’exécuter : la variable Nom_officiel existe-t-elle après cette ligne ?

semaine-08/pas-a-pas-decomposition/decomposer.js
// Renommer : la clé Nom_officiel devient la variable name
const { Nom_officiel: name } = museum;
// name vaut 'musée de la pêche'
console.log(name);

Enregistrez, lancez.

Vous devez voir, à la fin : musée de la pêche. La variable Nom_officiel, elle, n’existe pas : seule name a été créée.

Perdu ? Copiez rattrapage/decomposition/etape-2/decomposer.js à la place de votre fichier.

Étape 3 — Dans les paramètres. Une fonction qui reçoit un musée entier, et le décompose aussitôt.

Avant d’exécuter : label(other) affichera-t-il le premier musée ou le second ?

semaine-08/pas-a-pas-decomposition/decomposer.js
// Dans les paramètres : la fonction reçoit un musée
function label({ Nom_officiel: title, Ville: city }) {
  // title et city viennent du musée reçu
  return `${title} - ${city}`;
}
// Le même appel qu'avant : on donne un musée entier
console.log(label(other));

Enregistrez, lancez.

Vous devez voir, à la fin : musée bigouden — Pont-l'Abbé. L’appel n’a pas changé : on donne toujours un musée entier ; seule la fonction s’écrit autrement.

Perdu ? Copiez rattrapage/decomposition/etape-3/decomposer.js à la place de votre fichier.

Étape 4 — Dans un callback. Le même principe dans la fonction donnée à map (semaine 7).

Avant d’exécuter : que contiendra le tableau cities ?

semaine-08/pas-a-pas-decomposition/decomposer.js
// Dans un callback : chaque musée est décomposé
const cities = [museum, other].map(({ Ville: city }) => city);
// Un tableau des villes
console.log(cities);

Enregistrez, lancez.

Vous devez voir, à la fin : [ 'Concarneau', "Pont-l'Abbé" ].

Perdu ? Copiez rattrapage/decomposition/etape-4/decomposer.js à la place de votre fichier.

Variante à faire seuls

Pour ceux qui ont validé l’étape avant les autres. Écrivez une fonction department({ Departement }) qui renvoie Departement, avec ses commentaires, et appelez-la sur other. Réussi si : node decomposer.js affiche Finistère en dernière ligne.

Exercices — La décomposition

Comme en semaine 7 : chaque exercice est un fichier nom.js à la racine de semaine-08, avec sa consigne en commentaire, et son fichier de tests. Lancez toujours les tests avec le nom du fichier : node --test x1-decomposer.test.js. Les tests vérifient ce que renvoie la fonction ; la consigne vous dit comment l’écrire, avec une décomposition. Un seul exercice est un dossier, avec une page : x1c-fiche, dans l’entraînement.

Palier 1 — Décomposer un musée (25 min)

  1. x1-decomposer.js : placeLine(museum).
  2. Première ligne : const { Ville, Departement } = museum;.
  3. Réussi si : node --test x1-decomposer.test.js au vert.

Palier 1 : guidé. Durée : 25 min.

  1. Ouvrez x1-decomposer.js. placeLine(museum) renvoie « ville, département », par exemple 'Concarneau, Finistère'.
  2. Remplacez la ligne return ''; par deux lignes : d’abord const { Ville, Departement } = museum;, puis un return avec un littéral de gabarit qui utilise ces deux variables.
  3. Dans le terminal : cd ~/dwwm/dwwm-tp/semaine-08 (l’invite se termine par semaine-08), puis node --test x1-decomposer.test.js.
  4. Rituel : un commit (git add x1-decomposer.js, git commit -m "Ajoute la solution de x1").

Réussi si : node --test x1-decomposer.test.js affiche ℹ fail 0, et VS Code ne souligne rien en rouge.

Palier 2 — Dans les paramètres, renommer (40 min)

  1. x2-parametre-decompose.js : décomposer dans les parenthèses.
  2. x3-renommer.js : une fiche { name, city, department }.
  3. Réussi si : leurs tests au vert.

Palier 2 : recommandé, semi-guidé. Durée indicative : 40 min (20 min par exercice) ; ce qui n’est pas fini se termine mercredi dans le parcours d’autonomie.

  1. x2-parametre-decompose : shortCard renvoie « nom (ville) ». Décomposez directement dans les parenthèses de la fonction, en renommant Nom_officiel en name et Ville en city (comme l’étape 3 du pas à pas). Le corps n’a qu’une ligne : return. node --test x2-parametre-decompose.test.js.
  2. x3-renommer : toCard(museum) renvoie un nouvel objet { name, city, department }. Une ligne de décomposition qui renomme les trois clés, puis return { name, city, department }; : quand la variable porte le nom de la clé, on l’écrit une seule fois (semaine 7). node --test x3-renommer.test.js : le deuxième test vérifie que le musée reçu ne change pas.

Réussi si : node --test x2-parametre-decompose.test.js et node --test x3-renommer.test.js affichent ℹ fail 0.

Trois indices pour x2-parametre-decompose, du plus léger au plus complet. Ouvrez-les un par un : après chaque indice, essayez de nouveau avant d’ouvrir le suivant.

AstuceIndice 1 — l’idée

La décomposition s’écrit à la place du paramètre museum, entre les parenthèses de la fonction, avec ses accolades. Dedans, clé: nom range la valeur de la clé dans une variable qui porte un autre nom.

AstuceIndice 2 — le squelette

// Dans le corps, une seule ligne : renvoyer « name (city) », avec un littéral de gabarit
AstuceIndice 3 — la solution, moins une ligne

  // Il manque une ligne : le return, avec un littéral de gabarit.

Palier 3 — Un tableau, des valeurs par défaut (25 min)

Palier 3 : autonome. Durée indicative : 25 min ; ce qui n’est pas fini se termine mercredi dans le parcours d’autonomie.
