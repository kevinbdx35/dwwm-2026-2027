Objectifs

  • Réagir à une action de l’utilisateur avec addEventListener.
  • Distinguer deux événements : click (un clic, ou Entrée sur un bouton) et input (chaque caractère tapé).
  • Lire le texte d’un champ avec value, puis mettre la page à jour.

Comment se passe l’après-midi. Une seule notion : les événements. Ce matin, la page s’affichait une fois, au chargement. Cet après-midi, elle réagit : un clic, une lettre tapée, et elle change. Vous retrouvez tout le DOM de ce matin ; seul le moment change. Comme ce matin, tout se vérifie dans le navigateur : les tests reviennent demain.

Après-midi — Les événements

Les événements (15 min)

  • Pourquoi : que la page réagisse à l’utilisateur.
  • Écouteur : une fonction lancée à chaque événement.
  • click, input : deux types d’événements.

Pourquoi. Une page qui ne change qu’au chargement ne sert pas à grand-chose : on veut filtrer en tapant, afficher un détail en cliquant. Le navigateur prévient JavaScript de chaque action de l’utilisateur ; à vous de dire ce qui doit se passer.

Définition. Un événement est une action que le navigateur signale : un clic (click), un caractère tapé dans un champ (input)… element.addEventListener(type, fonction) pose un écouteur sur l’élément : la fonction donnée s’exécutera à chaque événement de ce type, et pas avant (MDN Web Docs, s. d.-a). Dans un champ, value donne le texte tapé (MDN Web Docs, s. d.-b).

Les événements, en image

Le texte du schéma : un clic sur le bouton (ou Entrée au clavier) ; l’écouteur, posé avec addEventListener, l’attendait ; la fonction donnée s’exécute, à chaque clic. En bas, le piège : show sans parenthèses est donnée au bouton ; show() est exécutée tout de suite.

Les événements, l’exemple minimal

Le premier programme de la notion, annoté :

semaine-08/exemple/app.js
const button = document.querySelector('#bouton');
const field = document.querySelector('#filtre');

1button.addEventListener('click', () => {
2  console.log('clic !');
});

3field.addEventListener('input', () => {
4  console.log(field.value);
});
1
Le type d’événement, puis la fonction à exécuter : ici, une fonction fléchée écrite sur place (semaine 7).
2
Le corps de la fonction ne s’exécute qu’au clic, à chaque clic.
3
input : à chaque caractère tapé ou effacé dans le champ.
4
value : le texte du champ, à cet instant.

Les événements — attention et vérification

AvertissementAttention

addEventListener('click', show()) : avec les parenthèses, show s’exécute tout de suite, une seule fois, au chargement ; ensuite, les clics ne font plus rien. Donnez la fonction, sans l’appeler : addEventListener('click', show), ou une fonction fléchée () => { … }.

  • Vérifiez : quel événement pour réagir à chaque lettre tapée ?
  • Dans l’écouteur, comment lire le texte du champ ?

Pas à pas ensemble — Rechercher en tapant (35 min)

  • Le formateur code, vous tapez en même temps, une étape à la fois.
  • Code et commentaires : // au-dessus de chaque ligne.
  • Dossier : pas-a-pas-evenements, fichier app.js.
  • Perdu ? Dossier rattrapage/evenements/, une étape à la fois.

Pas à pas. Ouvrez pas-a-pas-evenements/app.js : il contient déjà six noms de musées et une fonction showList(items), écrite avec le DOM de ce matin, qui vide la liste puis l’affiche. Ouvrez index.html avec Live Preview, puis dans le navigateur, F12, onglet Console.

Avant de commencer. Vous devez voir : un bouton « Cliquez-moi », « 0 clic », un champ « Filtrer les musées » et la liste des six musées ; aucune erreur dans la console. Chaque étape ajoute ses lignes à la fin d’app.js ; enregistrez, puis rechargez.

Étape 1 — Un écouteur sur le bouton. Posez un écouteur click qui écrit dans la console.

Avant d’exécuter : au chargement de la page, la console affichera-t-elle « clic ! » ?

semaine-08/pas-a-pas-evenements/app.js
// Le bouton de la page
const button = document.querySelector('#bouton');
// addEventListener : quand on clique, la fonction s'exécute
button.addEventListener('click', () => {
  // Visible dans la console, à chaque clic
  console.log('clic !');
});

Enregistrez, rechargez, puis cliquez trois fois.

Vous devez voir : rien au chargement ; puis « clic ! » à chaque clic (la console affiche un petit 3 à côté de la ligne). Au clavier, Tab jusqu’au bouton puis Entrée : un clic de plus.

Perdu ? Copiez rattrapage/evenements/etape-1/app.js à la place de votre app.js, puis repartez avec le groupe.

Étape 2 — Compter les clics. Une variable qui change, et un deuxième écouteur qui l’affiche.

Avant d’exécuter : pourquoi let, et pas const ?

semaine-08/pas-a-pas-evenements/app.js
// Le paragraphe du compteur
const counter = document.querySelector('#compteur');
// Le nombre de clics, qui va changer : let
let clicks = 0;
// Un deuxième écouteur sur le même bouton
button.addEventListener('click', () => {
  // Un clic de plus
  clicks = clicks + 1;
  // Le nouveau nombre, écrit dans la page
  counter.textContent = `${clicks} clics`;
});

Enregistrez, rechargez, cliquez.

Vous devez voir : « 1 clics », « 2 clics »… et toujours « clic ! » dans la console : les deux écouteurs s’exécutent à chaque clic. (« 1 clics » : c’est attendu ; le pluriel n’est pas corrigé aujourd’hui.)

Perdu ? Copiez rattrapage/evenements/etape-2/app.js à la place de votre app.js.

Étape 3 — Lire un champ. Un écouteur input sur le champ, qui recopie ce qui est tapé.

Avant d’exécuter : faudra-t-il appuyer sur Entrée pour voir le texte ?

semaine-08/pas-a-pas-evenements/app.js
// Le champ de saisie
const field = document.querySelector('#filtre');
// Le paragraphe qui recopie la saisie
const typed = document.querySelector('#saisie');
// input : à chaque caractère tapé ou effacé
field.addEventListener('input', () => {
  // field.value : le texte tapé dans le champ
  typed.textContent = `Vous avez tapé : ${field.value}`;
});

Enregistrez, rechargez, tapez « éco » dans le champ.

Vous devez voir : « Vous avez tapé : é », puis « éc », puis « éco », sans appuyer sur Entrée.

Perdu ? Copiez rattrapage/evenements/etape-3/app.js à la place de votre app.js.

Étape 4 — Filtrer la liste en tapant. Un deuxième écouteur input : filter (semaine 7), puis showList.

Avant d’exécuter : en tapant « éco », combien de musées restent ?

semaine-08/pas-a-pas-evenements/app.js
// Un deuxième écouteur input : filtrer la liste
field.addEventListener('input', () => {
  // Le texte tapé, en minuscules
  const query = field.value.toLowerCase();
  // filter : garde les noms qui contiennent ce texte
  const found = names.filter((name) => name.includes(query));
  // On réaffiche la liste avec les noms gardés
  showList(found);
});

Enregistrez, rechargez, tapez « éco », puis effacez.

Vous devez voir : deux musées (les deux écomusées) ; en effaçant, les six reviennent.

Perdu ? Copiez rattrapage/evenements/etape-4/app.js à la place de votre app.js.

Variante à faire seuls

Pour ceux qui ont validé l’étape avant les autres. Dans l’écouteur de l’étape 4, quand aucun nom ne correspond (found.length === 0), écrivez « Aucun musée » dans le paragraphe typed, avec son commentaire. Réussi si : taper « zzz » affiche « Aucun musée » et une liste vide.

Palier 2 : recommandé, semi-guidé. Durée indicative : 40 min (20 min par exercice) ; ce qui n’est pas fini se termine mercredi dans le parcours d’autonomie.

  1. e5-chercher-ville : six musées, un champ « Ville ».

Réussi si : dans e5, « r » affiche « 2 musées », « z » « Aucun musée », et un champ vidé affiche les six ; dans e6, chaque bouton affiche son musée, à la souris et au clavier ; aucune erreur dans la console.

Trois indices pour e5-chercher-ville, du plus léger au plus complet. Ouvrez-les un par un : après chaque indice, essayez de nouveau avant d’ouvrir le suivant.

AstuceIndice 1 — l’idée

À chaque lettre tapée, on refait toute la liste : garder les bons musées avec filter, vider la liste, la remplir de nouveau, puis écrire le nombre. Tout se passe dans la fonction de l’écouteur input.

AstuceIndice 2 — le squelette 
// Trouver le champ #ville, le résumé #resume et la liste #liste
// Écouter l'événement input du champ. Dans la fonction :
//   1. lire la valeur du champ, en minuscules
//   2. garder (filter) les musées dont la ville, en minuscules, commence par ce texte
//   3. vider la liste
//   4. pour chaque musée gardé : créer un <li> « nom - ville », l'ajouter à la liste
//   5. aucun musée gardé : écrire « Aucun musée » dans le résumé ; sinon, le nombre et « musées »
AstuceIndice 3 — la solution, moins une ligne 
const field = document.querySelector('#ville');
const summary = document.querySelector('#resume');
const list = document.querySelector('#liste');

field.addEventListener('input', () => {
  const query = field.value.toLowerCase();
  // Il manque une ligne : const found = … (filter, et la méthode trouvée dans MDN).
  list.textContent = '';
  for (const museum of found) {
    const item = document.createElement('li');
    item.textContent = `${museum.name} - ${museum.city}`;
    list.append(item);
  }
  if (found.length === 0) {
    summary.textContent = 'Aucun musée';
  } else {
    summary.textContent = `${found.length} musées`;
  }
});

Palier 3 — Un seul écouteur : la délégation (25 min)

  • e4-delegation : une page proche de e6, avec un seul écouteur.
  • data-id, event.target, closest : dans MDN.
  • Réussi si : le choix s’affiche, aucune erreur entre deux boutons.

Palier 3 : autonome. Durée indicative : 25 min ; ce qui n’est pas fini se termine mercredi dans le parcours d’autonomie.

Dans e6, chaque bouton a son propre écouteur : avec 1 200 musées, cela ferait 1 200 écouteurs. Faites une page semblable dans e4-delegation/app.js, avec un seul écouteur, posé sur la liste : c’est la délégation d’événements. L’écouteur reçoit un objet event ; à vous de trouver comment savoir sur quel bouton on a cliqué, et comment ranger l’identifiant du musée dans le bouton.

Réussi si : un clic (ou Entrée) sur un musée affiche « Musée choisi : nom - ville » ; un clic dans la liste, entre deux boutons, ne provoque aucune erreur dans la console ; app.js ne contient qu’un seul addEventListener.
