Objectifs

  • Ranger ce qui calcule (la logique) à part de ce qui affiche (l’affichage).
  • Tester la logique avec node --test, sans navigateur.
  • Afficher dans la page le résultat d’une fonction de la logique.

Comment se passe la matinée. Une seule notion : séparer la logique et l’affichage. Hier, tout le code était dans app.js, et vous vérifiiez tout à l’œil. Ce matin, chaque exercice a deux fichiers : logic.js calcule, et les tests le vérifient ; app.js affiche, et vous le vérifiez dans le navigateur. C’est l’organisation du projet n° 1, qui commence jeudi.

Matin — Séparer la logique et l’affichage

Rappel (5 min)

  1. Dans un écouteur : show ou show() ? Pourquoi ?
  2. Que renvoie [25, 8].toSorted((a, b) => a - b) ?
  3. Quelle commande Git crée une branche et s’y place ?

Trois questions courtes, sans regarder vos notes : la veille (lundi), la semaine passée, puis plus loin. Répondez sur une feuille ; la correction suit, à l’oral.

Séparer la logique et l’affichage (15 min)

  • Pourquoi : tester ce qui calcule, sans navigateur.
  • logic.js calcule ; app.js écrit dans la page.
  • La logique ne touche jamais à document.

Pourquoi. Hier, vous vérifiiez vos pages à l’œil, dans le navigateur. Avec 34 musées, puis des centaines quand les données viendront d’une API, l’œil ne suffit plus. Or Node, qui lance les tests, n’a pas de page : il ne connaît pas document. Tout ce qui calcule peut donc être testé automatiquement, à condition de ne pas dépendre du DOM. C’est aussi ce qu’attend le jury : des tests unitaires de la logique.

Définition. La logique (logic.js) calcule, filtre, formate : des fonctions qui reçoivent des données et renvoient un résultat, sans jamais toucher au DOM ; on la vérifie avec node --test. L’affichage (app.js) trouve les éléments de la page et y écrit le résultat de la logique ; on le vérifie dans le navigateur.

Logique et affichage, en image

Le texte du schéma : à gauche, logic.js, la logique : elle calcule, sans document, et node --test la vérifie. À droite, app.js, l’affichage : il trouve les éléments de la page et y écrit ; vous le vérifiez dans le navigateur. Une ligne import, en haut d’app.js, apporte les fonctions de logic.js.

Les lignes import (2 min)

AvertissementAttention

Les lignes import sont déjà écrites dans vos fichiers : ne les modifiez pas. Elles ne marchent que si la page est servie par Live Preview (une adresse en http://). Ouverte par un double-clic (file://), la page reste vide et la console parle de CORS (fiche « Lire un message d’erreur »). Les modules sont expliqués en semaine 10.

Pour l’instant, une seule chose à savoir : import { museumLabel } from './logic.js'; veut dire « prends la fonction museumLabel du fichier logic.js, qui est à côté ». C’est pour cela que la fonction porte le mot export dans logic.js. Dans index.html, la ligne <script type="module" src="app.js"></script> est, elle aussi, déjà écrite.

Logique et affichage — attention et vérification

AvertissementAttention

ReferenceError: document is not defined en lançant les tests : votre logic.js touche à la page. Déplacez cette ligne dans app.js : la logique ne fait que calculer et renvoyer.

  • Vérifiez : museum.Ville.toUpperCase() va dans quel fichier ?
  • Et list.append(item) ?

Pas à pas ensemble — Les musées de Bretagne (40 min)

  • Le formateur code, vous tapez en même temps, une étape à la fois.
  • Code et commentaires : // au-dessus de chaque ligne.
  • Dossier : pas-a-pas-logique : logic.js, app.js, essai.js.

Pas à pas. Ouvrez le dossier pas-a-pas-logique : logic.js déclare deux fonctions, encore vides ; app.js commence par les deux lignes import, déjà écrites ; essai.js appelle les deux fonctions et affiche leur résultat dans le terminal. Étape 1 — La logique : une étiquette. Dans logic.js, remplacez la ligne return ''; de museumLabel par les deux lignes du milieu du bloc ci-dessous : le commentaire et la ligne return. La première et la dernière ligne sont déjà dans le fichier.

Avant d’exécuter : que va afficher la première ligne de node essai.js ?

semaine-08/pas-a-pas-logique/logic.js
export function museumLabel(museum) {
  // Le nom, un tiret, la ville : un texte, sans document
  return `${museum.Nom_officiel} - ${museum.Ville}`;
}

Enregistrez, puis lancez node essai.js dans le terminal, depuis pas-a-pas-logique.

Vous devez voir, en première ligne : musée de Dinan - Dinan. La logique marche, sans aucun navigateur.

Perdu ? Copiez rattrapage/logique/etape-1/logic.js à la place de votre logic.js, puis repartez avec le groupe.

Étape 2 — L’affichage : la liste. À la fin d’app.js, affichez un <li> par musée, avec le texte de museumLabel.

Avant d’exécuter : combien de lignes dans la page ?

semaine-08/pas-a-pas-logique/app.js

Étape 3 — La logique : un filtre. Dans logic.js, remplacez la ligne return []; d’inDepartment.

Avant d’exécuter : que va afficher la deuxième ligne de node essai.js ?

semaine-08/pas-a-pas-logique/logic.js
export function inDepartment(museums, department) {
  // filter : garde les musées de ce département
  return museums.filter((item) => item.Departement === department);
}

Enregistrez, puis lancez node essai.js.

Vous devez voir, en deuxième ligne : 10 : les dix musées du Morbihan.

Perdu ? Copiez rattrapage/logique/etape-3/logic.js à la place de votre logic.js.

Étape 4 — L’affichage : le résumé. À la fin d’app.js, demandez les musées du Morbihan à la logique, puis écrivez leur nombre dans le résumé.

Avant d’exécuter : la liste va-t-elle changer ?

semaine-08/pas-a-pas-logique/app.js
// La logique calcule : les musées du Morbihan
const morbihan = inDepartment(MUSEUMS, 'Morbihan');
// Le résumé de la page

Enregistrez.

Vous devez voir : sous le titre, « 10 musées dans le Morbihan » ; la liste, elle, n’a pas changé : on n’a rien demandé d’autre.

Perdu ? Copiez rattrapage/logique/etape-4/app.js à la place de votre app.js.

AstuceIndice 3 — la solution, moins une ligne 
// logic.js
export function inDepartment(museums, department) {
  if (department === '') {
    return [...museums];

  // Il manque une ligne : le return, avec filter.
