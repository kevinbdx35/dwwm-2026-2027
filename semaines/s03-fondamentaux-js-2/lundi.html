Lundi 19/10 — Fonctions et démarche de débogage

Formateur

Kevin Bardoux

Date de publication

lundi 19 octobre 2026

Compétences visées : résolution de problème · apprendre en continu (anglais)
Livrable : les quatre premières fonctions du Problem set 1 au vert (p1-premier si le temps le permet).

Objectifs

  • Écrire une fonction avec des paramètres et un return.
  • Expliquer pourquoi une variable d’une fonction n’existe pas dehors.
  • Déboguer en quatre temps : lire, isoler, tester, corriger.
  • Faire passer les tests du Problem set 1.

Comment se passe la journée. Le matin, trois notions : la fonction, la portée, la démarche de débogage. L’après-midi, une : le reste %. Chacune suit le même ordre : pourquoi, définition, exemple, pas à pas, erreur fréquente, vérification ; un encadré « À retenir » termine chaque demi-journée. L’après-midi, le Problem set 1, validé par les tests.

Matin — Fonctions & portée · démarche de résolution de problème (lire l’erreur, isoler, tester) — exercices

Apport 1 — Les fonctions (10 min)

  • Pourquoi : écrire un calcul une fois, l’utiliser partout.
  • Fonction : un nom, des paramètres, un résultat renvoyé.

Pourquoi. En semaine 2, chaque programme lisait ses valeurs dans process.argv et affichait un résultat. Pour réutiliser un calcul (une aire, un prix TTC) avec d’autres valeurs, et pour le tester, on l’enferme dans une fonction.

Définition. Une fonction est un ensemble d’instructions qui effectue une tâche ou calcule une valeur ; on la déclare avec le mot-clé function, un nom, des paramètres entre parenthèses et des instructions entre accolades (MDN Web Docs, s. d.-b). L’instruction return termine la fonction et indique la valeur renvoyée (MDN Web Docs, s. d.-i). En semaine 2, le bloc personnalisé Scratch (rubrique « Pour aller plus loin ») était déjà une fonction.

Exemple, commenté ligne par ligne.

1function square(n) {
2  return n * n;
3}

4const result = square(4);
5console.log(result);
1
function déclare une fonction nommée square, avec un paramètre n : la valeur qu’elle recevra à chaque appel.
2
return arrête la fonction et renvoie le résultat de n * n à l’endroit qui l’a appelée.
3
L’accolade ferme la fonction. Jusqu’ici, rien ne s’exécute : la fonction est seulement déclarée.
4
square(4) appelle la fonction : pendant cet appel, n vaut 4. La valeur renvoyée, 16, est rangée dans result.
5
console.log affiche 16 dans le terminal.

Pas à pas. Le formateur tape chaque étape dans un fichier essai-fonction.js ; vous la refaites aussitôt.

  1. Écrivez la fonction square (lignes 1 à 3). Lancez node essai-fonction.js : rien ne s’affiche. Déclarer une fonction ne l’exécute pas.
  2. Ajoutez la ligne 5 : square(4) appelle la fonction. Le paramètre n vaut 4 pendant cet appel.
  3. return n * n renvoie 16 : result vaut 16.
  4. Ajoutez la ligne 6 et relancez : le terminal affiche 16.
  5. Ouvrez l1-bonjour.js, le premier exercice. Chaque exercice de la semaine a cette forme :
export function greet(firstName) {
  // TODO: replace the line below with your code.
  return `À faire (${firstName})`;
}
  1. Remplacez le return par le vôtre ; gardez export. export rend la fonction utilisable depuis un autre fichier, ici le fichier de test (MDN Web Docs, s. d.-a) (les modules sont détaillés en semaine 9). node --test l1-bonjour.test.js appelle votre fonction et vérifie ce qu’elle renvoie.

Vous devez voir : à l’étape 1, rien ; à l’étape 4, 16.

Apport 2 — La portée (10 min)

  • Pourquoi : un même nom dans deux fonctions, sans conflit.
  • Portée : une variable n’existe que dans son bloc { … }.

Pourquoi. Dans un programme, plusieurs fonctions utilisent des variables comme result ou total. Si elles se voyaient toutes, l’une pourrait modifier celle de l’autre par erreur.

Définition. La portée est la partie du programme où une variable est visible et utilisable (MDN Web Docs, s. d.-f) : une variable créée avec let ou const dans une fonction, ou dans un bloc { … }, n’existe que dans cette fonction ou ce bloc (MDN Web Docs, s. d.-b).

Exemple.

function double(n) {
  const result = n * 2;
  return result;
}

console.log(double(3)); // 6
console.log(result);    // ReferenceError

Pas à pas. Le formateur tape le code dans essai-portee.js ; vous le refaites aussitôt.

  1. Écrivez les lignes 1 à 6. Lancez le fichier : il affiche 6.
  2. Ajoutez la ligne 7 et relancez : ReferenceError: result is not defined.
  3. Lisez l’erreur : result n’existe pas à cet endroit, il n’existe que dans double.
  4. Pour garder le résultat, stockez ce que renvoie la fonction : const doubled = double(3);.

Vous devez voir, à l’étape 2 : 6, puis l’erreur. Les lignes qui commencent par at sont des détails pour plus tard : ignorez-les.

Portée — attention et vérification

AvertissementAttention

ReferenceError: … is not defined : la variable est utilisée hors de son bloc, ou son nom est mal écrit. Vérifiez où elle est déclarée.

  • Vérifiez : if (true) { const x = 1; } puis x : que se passe-t-il ?

Apport 3 — Déboguer avec méthode (20 min)

  • Pourquoi : trouver une erreur sans modifier le code au hasard.
  • Méthode : lire, isoler, tester, corriger.

Pourquoi. Changer le code au hasard jusqu’à ce que « ça marche » prend du temps et crée de nouvelles erreurs. Une démarche en quatre temps trouve la cause plus vite, et elle se raconte devant un jury.

Définition. Déboguer, c’est trouver et corriger la cause d’un comportement faux, en quatre temps : lire l’erreur (son type, son message, la ligne) ; isoler l’endroit où le problème apparaît (un console.log aide) ; tester le cas précis qui échoue (vide, limite, absent) ; corriger, puis relancer tous les tests.

Exemple. Une erreur affichée par Node.js :

/…/err.js:2
  return word[word.length - 1];
                   ^

TypeError: Cannot read properties of undefined (reading 'length')
    at lastLetter (/…/err.js:2:20)

Pas à pas. Le formateur lit l’erreur à voix haute ; vous notez chaque réponse.

  1. Lire le type : TypeError, une opération impossible sur une valeur du mauvais type (MDN Web Docs, s. d.-j). (Une ReferenceError signale une variable qui n’existe pas (MDN Web Docs, s. d.-g).)
  2. Lire le message : on lit length sur une valeur undefined.
  3. Lire l’endroit : fichier err.js, ligne 2, colonne 20, dans la fonction lastLetter.
  4. Isoler : quelle valeur vaut undefined ? word. La fonction a été appelée sans argument.
  5. Tester : appelez lastLetter() sans argument, puis lastLetter('chat'), pour comparer.
  6. Corriger : ajoutez une garde au début de la fonction, puis relancez tous les tests.

Message reproduit tel que Node.js l’affiche. La fiche Lire un message d’erreur rassemble les autres messages de Node (ReferenceError, SyntaxError, fichier introuvable).

Débogage — attention et vérification

AvertissementAttention

Corrigez une chose à la fois, puis relancez tous les tests : deux changements en même temps cachent lequel a réglé le problème.

  • Vérifiez : dans l’exemple, à quelle ligne est l’erreur ?

À retenir — ce matin

AstuceÀ retenir
  • Fonction : return renvoie le résultat ; console.log affiche.
  • Portée : une variable n’existe que dans son bloc { … }.

Le détail, notion par notion :

  • Fonction : function nom(paramètres) { … return …; } ; déclarer n’exécute pas, appeler exécute ; gardez export dans les exercices.

Après-midi — TP — « Problem set 1 » (validé par les tests)

Apport 4 — Le reste % (10 min)

  • Pourquoi : le dernier chiffre ; une division qui tombe juste.
  • a % b : le reste de la division de a par b.

Pourquoi. Le Problem set de cet après-midi demande d’additionner les chiffres d’un nombre (et, si le temps le permet, de reconnaître un nombre premier). Il faut pour cela le dernier chiffre d’un nombre, et savoir si une division « tombe juste ».

Définition. L’opérateur reste % donne le reste de la division de a par b (MDN Web Docs, s. d.-h) : 1234 % 10 vaut 4, le dernier chiffre ; 7 % 2 vaut 1. Un nombre n est divisible par d si n % d === 0. Pour enlever le dernier chiffre : Math.floor(1234 / 10) vaut 123 (MDN Web Docs, s. d.-d). Le résultat de % a le signe du premier nombre : -3 % 2 vaut -1.

Exemple.

console.log(1234 % 10);             // 4 : le dernier chiffre
console.log(Math.floor(1234 / 10)); // 123 : sans le dernier chiffre
console.log(12 % 3 === 0);          // true : 3 divise 12

Pas à pas. Le formateur montre chaque étape ; vous la refaites aussitôt.

  1. REPL : 1234 % 10, puis 123 % 10, puis 12 % 10.
  2. Math.floor(1234 / 10) : le nombre sans son dernier chiffre.
  3. 12 % 3 puis 12 % 5 : lequel « tombe juste » ?

Vous devez voir :

Reste — attention et vérification

AvertissementAttention

Tester « impair » avec n % 2 === 1 échoue sur les négatifs (-3 % 2 vaut -1). Testez « pair » avec n % 2 === 0.

  • Vérifiez : que vaut 57 % 10 ?
