Charte IA — Formation DWWM 2026-2027

Formateur

Kevin Bardoux

Date de publication

vendredi 2 octobre 2026

Cette charte fixe ce que vous pouvez faire avec les outils d’intelligence artificielle (assistants conversationnels, autocomplétion de code, agents de codage) pendant la formation. Elle est présentée le jour de la rentrée et s’assouplit par paliers, au fur et à mesure que vos bases se consolident.

Pourquoi des paliers

Un développeur qui utilise l’IA sans savoir coder ne peut ni vérifier ce qu’elle produit, ni corriger ses erreurs, ni repérer ses failles de sécurité. Le jury du titre professionnel vérifie que vous maîtrisez vous-même les compétences : il vous questionne sur votre code, et le questionnaire professionnel se passe sans internet.

L’objectif est donc de poser les bases d’abord sans IA pendant trois semaines, puis avec l’IA comme tuteur, puis comme assistant à qui l’on pose des questions, puis comme assistant qui agit sous votre contrôle, et enfin comme en entreprise.

Les paliers

Palier Période L’IA est…
0 Semaines 1 à 3 (8 → 23 octobre) absente
1 Semaines 4 à 11 (à partir du 26 octobre) un tuteur (CS50.ai)
2a Semaines 12 à 15 (à partir du 4 janvier) un assistant à qui l’on pose des questions
2b Semaines 16 à 20 (à partir du 1er février) un assistant qui agit, sous votre contrôle
3 Principe en semaine 21 (12 mars), pratique en semaine 24, stage compris un agent que vous pilotez

CS50.ai reste disponible à tous les paliers suivants pour se faire expliquer une notion.

Palier 0 — Sans IA

  • Aucun assistant IA pour écrire, compléter, corriger ou expliquer votre code.
  • L’autocomplétion par IA est désactivée dans l’éditeur (Copilot, Codeium, etc.).
  • Autorisé : la documentation officielle (MDN, Node.js…), les moteurs de recherche, les forums, vos camarades et le formateur.
  • Le formateur peut faire des démonstrations avec l’IA ; vous, non.

Palier 1 — IA tutrice : CS50.ai

L’IA vous aide à comprendre, jamais à faire à votre place. L’IA tutrice de la formation est CS50.ai (cs50.ai), le « canard » du cours CS50 de Harvard, un outil d’IA conçu pour aider les étudiants face à leurs difficultés (notes de CS50x sur l’IA, https://cs50.harvard.edu/x/notes/ai/). C’est une adaptation de ChatGPT conçue pour se comporter comme un bon tuteur, qui mène vers la réponse au lieu de la donner (documentation de CS50.ai, https://cs50.readthedocs.io/cs50.ai/). Il répond en français.

  • Connexion : avec votre compte GitHub (créé le lundi de la semaine 4).
  • Où : dans le navigateur, sur cs50.ai, à côté de VS Code. Le canard est aussi intégré à « Visual Studio Code for CS50 », l’environnement en ligne de CS50 (cs50.dev, qui fonctionne dans GitHub Codespaces : https://cs50.readthedocs.io/cs50.dev/), mais pas dans notre VS Code.
  • Les cœurs : 10 questions, puis une de plus toutes les 3 minutes (constaté à l’usage). C’est un atout : réfléchissez, cherchez, puis posez une question précise.
  • Autorisé : demander une explication, la reformulation d’un message d’erreur, un indice, des questions pour vous faire réfléchir, un quiz pour réviser.
  • Interdit : lui demander du code solution, lui coller l’énoncé entier d’un exercice, lui faire rédiger un texte à rendre.
  • Ce qu’on n’y colle jamais : des données personnelles (les vôtres ou celles d’autrui), des secrets (mots de passe, clés, jetons), le code ou l’énoncé d’un sujet d’évaluation. CS50.ai est réalisé avec le soutien de Microsoft et d’OpenAI (https://cs50.ai) : vos questions sont envoyées à des services extérieurs à la formation. D’après l’équipe de CS50, elles passent d’abord par CS50.ai, qui en retire les données personnelles, puis sont traitées par GPT-4, hébergé sur Microsoft Azure (Liu et al., « Teaching CS50 with AI », SIGCSE 2024 : https://cs.harvard.edu/malan/publications/V1fp0567-liu.pdf). La règle reste la même : rien de personnel ni de secret.
  • Évaluations : ECF et épreuves « sans IA » se font sans CS50.ai.
  • Les autres assistants IA ne sont pas utilisés au palier 1. L’autocomplétion par IA reste désactivée.

Palier 2 — IA assistante : GitHub Copilot dans VS Code

L’IA assistante de la formation est GitHub Copilot, dans VS Code (source : documentation de Copilot, https://docs.github.com/en/copilot/get-started/plans). Le palier 2 se fait en deux temps : d’abord vous lui posez des questions (2a), puis vous la laissez agir, en validant chacune de ses actions (2b).

  • Offre commune : Copilot Free, activée avec votre compte GitHub, sans paiement. Elle est limitée : 2 000 complétions par mois, et un nombre réduit de questions au chat. Si vous avez obtenu Copilot Student par GitHub Education, vous pouvez l’utiliser, mais aucun exercice n’en dépend.

  • Mise en route (lundi de la semaine 12) : Copilot est intégré à VS Code, sans extension à installer : décochez le réglage chat.disableAIFeatures, puis, sur l’icône Copilot de la barre d’état, choisissez « Use AI Features » et connectez-vous avec votre compte GitHub (source : https://code.visualstudio.com/docs/copilot/setup). Dans les réglages Copilot de votre compte GitHub (github.com → Settings → Copilot), désactivez l’utilisation de vos données pour l’entraînement des modèles (« Allow GitHub to use my data for AI model training » : Disabled) ; source : https://docs.github.com/en/copilot/how-tos/manage-your-account/manage-policies. #### Palier 2a — Copilot en mode question (semaines 12 à 15)

  • L’autocomplétion en ligne reste désactivée : réglage github.copilot.enable à false pour * (source : https://code.visualstudio.com/docs/copilot/ai-powered-suggestions).

  • Autorisé : le chat, pour poser des questions : expliquer une notion ou un message d’erreur, relire votre code, proposer des cas de test, critiquer une solution, générer des données de test.

  • Vous écrivez le code vous-même. Si le chat montre un extrait, vous le retapez en le comprenant ; pas de copier-coller d’une fonctionnalité.

  • Interdit : l’autocomplétion, le mode agent et toute modification de vos fichiers par l’IA.

  • Projet commun du centre (semaines 14 et 15) : les règles fixées par le centre s’appliquent en priorité ; à défaut, le palier 2a.

Palier 2b — Copilot en mode agent, chaque action validée (à partir de la semaine 16)

L’IA peut produire du code, à condition que vous puissiez l’expliquer ligne par ligne sans elle.

  • Activés en plus : l’autocomplétion en ligne (github.copilot.enable repassé à true) et le mode agent.
  • Chaque action est validée. Le niveau de permission reste le niveau manuel, celui par défaut : pour chaque outil ou commande, lisez ce qui va être exécuté avant de choisir Allow, pour une seule utilisation (source : https://code.visualstudio.com/docs/agents/run/approvals).
  • Interdit : toute approbation automatique : réglage chat.tools.global.autoApprove, commandes /yolo et /autoApprove, niveau « Allow all », approbation pour la session, l’espace de travail ou pour toujours. Interdit aussi : l’acceptation automatique des modifications (réglage chat.editing.autoAcceptDelay).
  • Chaque diff est relu : pour chaque modification, Keep pour l’accepter ou Undo pour la rejeter, une à une (source : https://code.visualstudio.com/docs/copilot/chat/review-code-edits).
  • Le commit se fait à la main : vous écrivez vous-même le message, jamais l’agent.
  • Si le mode agent n’est pas inclus dans votre offre Copilot : autocomplétion, et modifications proposées dans le chat, appliquées et relues une à une ; commit à la main. Les règles de relecture restent les mêmes.

Règles communes aux paliers 2a et 2b

  • Obligatoire : relire, tester et comprendre tout code généré avant de le commiter. Vérifier en particulier tout ce qui touche à la sécurité (authentification, validation des entrées, requêtes SQL) et vérifier que chaque paquet proposé existe vraiment avant de l’installer.
  • Règle de l’explication : tout code proposé par Copilot doit pouvoir être expliqué ligne par ligne, sans l’IA. Sinon, on ne le garde pas.
  • Interdit : générer une fonctionnalité entière que vous ne comprenez pas.
  • Évaluations : Copilot est désactivé pendant les ECF (semaines 18 et 21 comprises) et devant le jury (dans VS Code, réglage chat.disableAIFeatures coché). Seul document autorisé : votre aide-mémoire d’une page, écrit à la main.
  • Lors des revues de code, le formateur peut vous demander d’expliquer n’importe quelle ligne.

Palier 3 — Agent piloté, en conditions d’entreprise

Vous utilisez l’IA comme un développeur professionnel : agents de codage, lecture critique de diff, comparaison d’outils.

  • Semaine 21 : le principe. L’agent travaille sur une tâche que vous avez décrite (une issue) ; vous relisez, corrigez ou refusez sa proposition comme la Pull Request d’un collègue.
  • Semaine 24 : la pratique, et un banc d’essai qui compare modèle local et service en ligne.

Ce qui change par rapport au palier 2b :

  • L’agent traite une issue entière, sur une branche dédiée (agent/issue-12) ; ses modifications se relisent ensemble, dans le diff de la branche, comme la Pull Request d’un collègue (grille de revue de la semaine 24), et non plus une à une.
  • Ce qui ne change pas : les commandes du terminal restent validées une par une, au niveau de permission manuel. Toute approbation automatique reste interdite (les réglages et commandes listés au palier 2b ; dans Cline : « Execute safe commands », « Execute all commands » et le mode YOLO).
  • Le commit final et la fusion restent faits par vous : vous écrivez le message de commit, vous ouvrez la Pull Request, vous fusionnez après la relecture de votre binôme. L’agent ne commite pas et ne fusionne pas.

Les outils (offres vérifiées le 02/10/2026) :

  • Outil principal : Copilot Free en mode agent, dans VS Code (déjà utilisé au palier 2b).

  • Solution de repli : Cline + Mistral (offre gratuite de Mistral). Avant toute requête, l’utilisation de vos données pour l’entraînement est refusée dans la console de Mistral (vérifié en séance). La clé d’API n’est saisie que dans Cline, qui la garde dans votre dossier personnel, hors de vos dépôts ; jamais dans un fichier du projet, une invite ou un message.

    • Une clé dédiée au cours, créée sur l’offre gratuite de Mistral, sans moyen de paiement enregistré, et qui ne sert à rien d’autre ; nommez-la dwwm-s24 et donnez-lui une date d’expiration (la fin de la S24, ou la fin de la formation si vous gardez Cline + Mistral comme solution de repli).
    • Révoquée à la fin de la S24, ou à la fin de la formation : dans la console de Mistral, menu API Keys, supprimez la clé dwwm-s24 ; dans Cline, effacez la clé du fournisseur Mistral. Une clé publiée par erreur se révoque tout de suite, de la même façon.

  • Cline + Ollama (modèle local) : seulement pour le banc d’essai, sur les ordinateurs qui ont assez de mémoire vive.

  • L’agent cloud de Copilot (assigné à une issue) n’est pas inclus dans Copilot Free : démonstration par le formateur si possible, jamais exigé.

  • Copilot Student (GitHub Education) : facultatif. Le centre peut fournir une attestation de formation ; chaque stagiaire décide s’il l’envoie à GitHub.

  • En stage, la politique de l’entreprise s’applique en priorité : demandez à votre tuteur quels outils sont autorisés.

  • Vous restez responsable de tout le code que vous livrez.

Règles valables à tous les paliers

  1. Évaluations sans IA. Les ECF, contrôles et questionnaires blancs marqués « sans IA » se font sans aucun assistant ni accès internet.
  2. Transparence. Chaque projet contient une section « Usage de l’IA » dans son README : quels outils, pour quoi faire. Un usage déclaré n’est jamais reproché s’il respecte le palier.
  3. Données. Ne collez jamais dans un outil d’IA de données personnelles, de mots de passe, de clés d’API ou de code confidentiel (en stage, le code de l’entreprise).
  4. Esprit critique. L’IA se trompe, invente des fonctions qui n’existent pas et produit parfois du code vulnérable. Tout ce qu’elle produit se vérifie.
  5. Dossiers et certification. Le dossier de projet et le dossier professionnel décrivent votre travail. Le jury vous interroge dessus : vous devez pouvoir tout expliquer. L’IA peut corriger l’orthographe et la grammaire de votre propre texte ; elle ne rédige pas à votre place. Aucune donnée de l’entreprise de stage (code, noms de clients, captures, documents) n’entre dans un outil d’IA.
  6. CV, lettres et candidatures (semaines 26 et 27). Un CV contient vos données personnelles (nom, adresse, téléphone, adresse e-mail, parcours) : il n’entre dans aucun outil d’IA en ligne, ni une lettre de motivation qui en contient. Seule la correction de l’orthographe est permise, avec un correcteur local, qui n’envoie rien sur internet : par exemple Grammalecte, extension de LibreOffice (logiciel libre, l’analyse se fait sur votre ordinateur). L’IA ne rédige ni votre CV, ni vos candidatures : le recruteur, comme le jury, vous interroge sur ce que vous avez écrit.

En cas de manquement

Un premier manquement donne lieu à un échange avec le formateur ; le travail concerné est refait dans les conditions du palier. En cas de manquements répétés, les dispositions du règlement intérieur de l’établissement s’appliquent.
